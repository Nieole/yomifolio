## 责任与内部边界

浏览器应用负责藏书浏览、编排、阅读与管理交互。身份与角色由 `auth` 持有，`App` 配置路由；`session` 协调全站连接和失效；功能 hooks 持有查询、功能投影及补拉；页面拥有筛选、选择、展开、弹窗与待提交草稿。页面卸载不能销毁应持续存在的全站连接，连接重建也不能成为清空页面编辑态的理由。

Layout 路由位于 `ApplicationSessionScope` 内；全屏阅读器与作品群图不在该作用域，不能要求所有页面依赖会话 Provider。`features/task-observation` 共享任务快照与气泡投影，不由每个页面各建 SSE；`features/external-library` 管传输会话功能状态。本机阅读数据的生命周期归 `mm-web-reader`。

## 服务边界

API 是规则与授权的最终裁决者；前端守卫只避免向无权限用户呈现无法使用的整屏管理操作。`src/api/generated.ts` 是生成的服务契约，不手工维护平行类型。功能异步请求必须校验所请求的作用域仍有效，避免切库或切系列后旧结果覆盖新视图。

locale 与 theme 提供表现偏好，不混入业务事实或用户在线会话。普通设备偏好（含阅读偏好）统一使用 `yomifolio_*` 键，由 `src/utils/browserPreferences.ts` 集中定义；新键存在时优先，否则兼容读取并复制旧 `manga_manager_*` / `manga_*` 值。保留旧值以便写入失败后重试，storage 不可用不得导致应用崩溃，解析与取值校验仍归调用方。此迁移不涉及离线书、队列、owner、cache 或认证与 Service Worker 身份。Layout 与 Dashboard 的资料库内部事件统一使用 `yomifolio:open-add-library` / `yomifolio:open-edit-library`。

验证命令、依赖说明归 `AGENTS.md` 和 `web/README.md`，不在此复制。

核对入口：`src/App.tsx`、`src/session/ApplicationRoutes.test.tsx`、任务观察 hooks 与页面切换竞态测试。

## 全局搜索会话

搜索会话是功能状态，不由 Layout 与弹层各建一份；输入、迟到隔离、选择与分页交互归 `mm-web-search`。它消费服务端排名，不承担后端查询规则或授权。

## 视口内可达性

弹性输入框与连续长标题必须允许收缩，不能将旁边的清空、目录浏览、编辑或快照操作挤出容器。标题可截断并保留完整名称提示；目录选择统一由 `DirectoryPicker` 保证输入与浏览按钮的空间分配。

跨裁切容器的操作菜单复用 `AnchoredPopover` 的文档根挂载、锚定和视口避让能力；业务适配器保留操作目标、权限和回调，不复制定位规则。触屏用户不能依赖鼠标悬停才能发现菜单入口。

响应式交互须在实际组件组合与浏览器布局下验证边界、命中目标及滚动后的可达性；仅验证 JSX 类名不能证明内容可见或可点击。

## MCP 凭据设置

`/settings/mcp` 是独立的管理员命令界面，不加入配置草稿保存。页面使用生成的 Credential、Restrictions 与 IssuedCredential 契约，提供真实用户选择、显式资料库与独立能力限制、一次性密钥显示、仅减权编辑及确认撤销；使用命令返回的权威投影更新列表，不以随后刷新失败冒充写入失败。密钥只驻留该页内存，隐藏、离页或切换用户即丢弃，不存入浏览器持久化。未完成请求在离页后不得回填；普通用户既不显示导航，也不渲染管理界面，最终授权由服务端负责。


## MCP 元数据操作历史

`/settings/metadata-operations` 是独立管理员查询和撤销界面，不进入配置草稿。页面显示身份、时间、单系列结果、字段前后值、短理由、来源链接和原始评分/公式，按服务器游标追加分页。撤销须确认，以同一命令键保留失败重试身份，采用服务器权威结果；conflict 不显示已恢复，成功关联原操作为已撤销。当前是否仍可安全撤销由服务端提交时检查，不以按钮存在保证。离页或切换用户不回填旧请求，普通用户不渲染或请求管理投影。


封面操作历史同时显示保留的原图/选定图、虚拟材料前后键、比较短理由与操作结果；撤销操作按方向展示恢复前后图片。明确提示封面与涉及文字一起恢复，后续人工封面、相关文字或当前锁可阻止撤销；按钮不保证可撤销。图片仅使用服务端材料键经现有 thumbnail 路由，不渲染任意来源图片 URL。

作者校正沿用此历史界面：以逐行“姓名 · 角色”呈现作者组前后差异，同时显示来源和校正短理由；撤销确认与服务器冲突反馈不变，不提供全库身份合并或本地乐观恢复。

提案裁决收据使用服务器 adjudication.status 与 accepted（不是请求的 mode）展示全部拒绝、部分已应用仍待裁决及补充后关闭，附提案 ID 与短理由。收据是当时事实，不冒充最新提案状态；仍按 outcome 判断本次实际变更与撤销入口，纯关闭不提供内容 Undo，已应用操作仍可单独符合条件地恢复。

历史页提供每操作的“清理撤销材料”显式命令，常驻说明永久丢弃恢复快照/必要旧图片、无自动到期、最小审计与在用图片保留。不增加逐批确认工作流。保留不确定网络失败的同一请求键重试身份；采用服务器 complete/partial/pending 结果并显示不可恢复提示，partial 不冒充全部文件回收。undo_unavailable 的操作不展示旧图片/前后恢复值或 Undo 按钮；清理不是删除藏书。离页/切用户不回填结果。

`useOperationCleanups` 通过持久 `Operation.cleaned_by` 去重读取清理结果，卸载/刷新后仍显示 pending/partial/complete。仅服务器提供原网页执行者的 `retry_request_key` 且目标匹配时提供 pending 继续按钮；隔离后的操作绝不分配新键，其他执行者的结果只供检查。查询失败可重新读取，取消/网络失败保留原键重试；结果键不写浏览器持久存储。

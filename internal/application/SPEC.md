## 责任

组合跨功能的完整应用用例，负责同步保存与后台工作的效果交接。后台工作让手动、监听、定时、串联和恢复走同一条发起链；`Runs.Start` 是共享准入入口的应用包装，不是第二个调度器，`DecorateRunContext` 为任务日志附上本次运行与诊断键。同步配置发布、资料库管理和系列编辑不因位于应用层就必须任务化。

扫描编排持有扫描声明、封面批派发及清理收尾；维护编排组合重建、哈希回填和保留清理；智能生成编排持有付费生成的运行策略与生命周期；磁盘作业编排组合外部传输与 ComicInfo 回写；迁移编排交接监听、缓存和外部会话。各能力声明自己的重启方式，由 `mm-runtime` 统一装配。

系列识别（识别结论与状态、证据包预取与重搜、agent 领取与裁决、纠正、巡检上报及所有者决定）归 `application/identification`，契约见子节点 `mm-identification`；识别确认后的元数据补充、撤回与改正由下述 enrichment 在识别的同一写事务内执行。

## 边界与内部边

后台工作通过 `Runs` 发起；同步用例直接返回保存结果，不以运行状态代替提交事实。应用能力通过窄效果端口交接监听、传输发布和缓存失效，不得让功能实现反向依赖应用编排。迁移编排注入可暂停输入和清理派生状态的钩子，不复制持久迁移规则。

`configuration` 返回同一次串行保存的配置、校验与发布结果，区分文件保存、共享快照发布和消费者生效时机；可变配置及跨持久参与者补偿仍归 `config.Manager`。`libraries` 区分资料库已保存、watcher 是否接管、初始扫描是否准入及警告；删除先封闭访问、等待真实占用退出，再独占删除并退休身份，后置效果不能冒充未提交。已有藏书的根路径变更须交给迁移用例。

`seriesediting` 组合来源规则、事务和返回投影：单系列手工保存将元数据、统计和结果读取放在同一事务内，失败不提交；批量增量编辑的元数据整体提交，后置统计失败单独返回，不撤销已提交编辑。来源规则仍归领域能力，SQL 与事务执行仍经持久端口，不在 HTTP 适配器中重建保存配方。

系统级索引重建等待所有已发起的强制资料库扫描；任一单库摄入失败都携带资料库身份与路径向维护运行传播，不能记录 completed。扫描错误可合并；上下文取消仍优先作为取消结果传播，收尾等待已发起扫描结束。

不得把规则、SQL 事务或协议请求解析搬进总编排对象。后台运行的能力、重启安全性与取消语义按具体工作声明，不能因为有通用控制端点就承诺所有工作可暂停、可取消或自动续跑。

维护扫描错误传播由真实 HTTP 回归 `TestSearchMaintenanceMissingLibraryFailsHTTP` 守卫；有效归档成功路径由 `TestSearchFullMaintenanceWithRealArchiveHTTP` 守卫。

已知限制：系统级重建与单库扫描具有不同任务身份，仍可能同时扫描同一库；资料库清理刻意脱离取消，以完成收尾；待执行封面批保存在无固定上界的内存队列中。

## 受限委托访问

`delegated.Service` 拥有独立凭据管理及受限系列读取；`delegated.SQLStore` 是由装配根创建的持久端口实现，不向协议适配器交出 SQL。管理用例在事务内重新检查当前管理员及目标用户，签发绑定真实用户、显式资料库集合与四项独立能力（read、metadata_write、scan_control、cleanup）的凭据；签发与收窄拒绝其它能力名。库内凭据存着的其它旗标（如 internal_llm）读取时视为不存在：不授权、不进清单与列表，收窄后即从存储中消失。`GrantedCapabilities` 给协议层的是凭据当前的**有效**能力：带着且 `Authorize` 会认的那些，普通用户的凭据只剩 read，工具清单与初始化说明因此不列它用不了的工具。`mcp_model_operations`、`mcp_model_calls` 里的额度记录保留，没有读取入口。空集合不表示全部；已有凭据只能移除资料库或能力，不能换用户、改名、恢复已撤销项或扩权，扩权须另签发。原始 256-bit 随机 Bearer 密钥只在签发结果出现一次，库内仅保留 SHA-256 摘要；撤销状态持久保留，密码变更的事务失效规则归 `mm-database`。

`delegated.Subject` 只携带 user_id 与 credential_id，供后续运行与操作持久归属；它不是授权快照，不应接受 agent 自报的身份。`Authenticate` 从密钥解析当前主语；`Authorize` 每次查询当前凭据、用户存在性、改密要求与角色，求当前账号许可、凭据资料库及能力的交集。当前账户模型没有额外的用户资料库 ACL，普通用户已有全库目录读权限，但委托只读凭据仍受所选资料库限制；非 read 能力一律还要求当前管理员身份，普通用户不获得管理权限。

### 受限发现与本地线索

`FindSeries`、`ListBooks`、`GetBookClues` 拥有完整只读用例；SQL 持久端口负责查询，`bookcontent` 负责实际本地内容。协议层不直查 DB 或拼接归档访问。查询不扫描、不写入维护状态、不改变网页筛选或扫描摄入。

- 系列条件取交集：`library_ids` 内 OR（省略或空数组取当前凭据的显式资料库集合），`series_ids` 内 OR（最多 50 个明确目标），时间区间与 `missing_fields` 之间 AND，`missing_fields` 内 OR。显式越界资料库或系列即拒绝整个请求，即使其他过滤条件会排除它；未知明确系列同样拒绝。资料库最多 256 个。
- `added_from` 包含、`added_before` 不包含，均为 RFC3339 时间，比较系列持久 `created_at` 的时间点；上下界都提供时须严格递增。它不是完整增量水位，不承诺扫描完成或维护状态。
- 缺失字段只接受 title、summary、publisher、status、language、rating、authors、tags、source_links；描述字段按 SQLite trim 后空或 NULL，评分仅 NULL，集合按没有关联成员判定。零分不是缺失；锁不参与发现。列出的字段任一缺失即命中，便于一次找出所有缺元数据的系列；不解析来源内容或标签的语义。
- 系列与书均按稳定 ID 升序 keyset 分页：`after_id` 排他，非负；`limit` 省略或 0 为 20，最大 50，负数或超限拒绝。返回 `next_after_id` 仅在还有匹配结果时存在。游标不是授权，后续请求仍重查权限；无跨请求快照，调用方改变条件即开始另一查询。
- 系列返回稳定系列/资料库 ID；书返回稳定书/系列/资料库 ID、名称、标题、卷号、话号、页数及末级目录名/文件名。按书读取须同时核对所属系列和资料库一致，当前账号与凭据对实际对象的 read 授权不能绕过。`GetBookClues` 按稳定书 ID 按需取单书 ComicInfo，不将整本归档或任意路径暴露给调用方。
- ComicInfo 只返回已建模的身份字段（标题、系列、卷号、话号、作者、画师、出版社）；原始 XML 最多 64 KiB，声明大小和实际解压均受限。状态区分 available、missing、corrupt、unreadable、unavailable、too_large，异常不伪造空元数据或把缺失宣称为有效证据；底层路径和错误不返回。
- 单次成功的结构化 JSON 最多 240 KiB，为 256 KiB 工具结果预留协议开销；超限整个请求失败，不静默截断证据。协议层另以文本块重复同一份 JSON，这份副本不计入此上限。调用方可减小分页或缩小目标；单对象仍超限须明确失败。

### 受限图片证据

`SeriesCover` 与 `PageThumbnails` 是完整只读应用用例，复用同一 `bookcontent.Service` 与资料库访问资格。封面按目录规则选择系列内首个已有封面的书（sort_number、name，稳定 ID 破同序），读取当前封面缓存，而非假定第一页是封面；不存在缓存明确失败。页面请求必须给出系列与书 ID，两者及实际资料库须一致；直接书 ID 不能绕过系列或库授权。每次按当前用户 ∩ 凭据 ∩ 实际对象重新授权，物化完成后再查当前权限。响应与错误不携带宿主路径。

- `PageThumbnails` 只接受 1–3 个不同的一基页码；空数组、重复、非正数、越界或任何一页失败，整个请求失败，不返回部分证据。没有 after/offset/cursor、整书模式或原始文件回退。重复请求仍只能得到固定低分辨率证据，不提供无损/原图拼接通道；这不是跨请求阅读次数配额。
- 固定 JPEG、最长边 384 像素、保持比例且不放大，每张编码后最多 96 KiB。使用严格解码/重编码路径，不复用普通阅读器的处理失败原图回退；输入解压与像素限制归 `mm-bookcontent`、`mm-images`。
- 应用结果将图片字节计入 base64 后的实际 JSON 大小，并为协议预留 4 KiB；总预算为 256 KiB。超限请求失败，调用方应减少页数，不自动降为原始文件或静默截断。最终 wire framing 与调用方 JSON-RPC ID 另由 `mm-api` 最终检查，不能只以压缩图片字节数宣称满足预算。
- `ImageEvidence` 的结构化内容只含系列/书 ID 以及按请求顺序的页码、实际宽高；图片仅在 MCP image content 出现一次。工程取值偏向识别而非阅读：三页足以比较少量关键视觉线索，384 像素和 JPEG quality 65 控制细节与成本，单图预算不意味着三张图一定能同时装入整体预算。

`GetSeries` 对实际系列所属资料库重新授权；未知与越界标识均拒绝，白名单返回稳定系列/资料库 ID、名称、标题与末级目录名，不含宿主路径或阅读信息。扫描控制通过 `StartScan`、`GetRun`、`ListRuns`、`WaitRun`、`CancelRun` 复用现有扫描与共享运行引擎。直接访问和列表只暴露同一凭据拥有、且当前仍有实际资料库及声明能力的运行；凭据在该资料库有任一能力即可列运行（只有 metadata_write 的凭据也能列出自己的重搜运行，用户决定），每条再按它自己的能力过滤；默认拒绝普通网页任务、其他凭据的任务和未知标识。投影不含路径、技术错误或重启参数。列表按带末尾冒号的完整凭据命名空间前缀在存储分页前筛选，不用精确变体代替命名空间；再按当前声明能力检查每条，内部继续越过不可见页直至填满或耗尽，避免收紧能力后较新不可见运行挡住较旧可见运行。列表每页最多 100 条，按稳定 run_id 降序游标查询；等待最多 30 秒，等待期间及返回前重查权限。超时、HTTP/stdio 断连或等待请求取消都不取消业务运行。

`PrepareRun` 为单资料库委托工作持久保存用户、凭据、实际资料库和所需能力（运行 Args），并以凭据隔离任务变体，避免不同权限主体或网页扫描的队列声明互相合并。归属与新运行在同一事务落地，失败不得执行。`ExecutionCheck` 在排队放行及任务体执行前重新鉴权；执行上下文的 `taskcontrol.Wait` 检查点检查当前权限，失效后协作取消整个上下文。已提交内容不回滚，已发网络请求与费用不保证追回。扫描仅作非强制摄入准备，不串联独立封面或哈希回填任务，避免绕过委托归属及持续授权；普通扫描的串联行为不变。例外是增量证据包预取（用户决定）：委托扫描收尾与普通扫描一样串联它，它是不带委托归属的系统运行，只处理该资料库里扫描新建或待刷新的系列，只读本地 ComicInfo 并访问外部来源，不写系列元数据。

run_id 标识一次已接纳执行，不是系列变更的 operation_id，也不是请求幂等键。扫描请求重试不保证 exactly-once：仅在同凭据、同任务已有排队项时沿用既有队列合并并返回 coalesced，保留原声明；否则接纳另一条运行。客户端不确定受理结果时应先列表查询，不可把合并当作幂等保证。系列操作需独立持久标识，不得复用扫描合并计数。委托任务变体不登记重启/重试入口：重启只将遗留运行记为 interrupted，绝不自动继续扫描或重新发出付费调用；重新发起须当前授权。

供来源、写入及撤销用例复用的边界是 `PrepareRun`（准入/归属）、`Checkpoint`（外部请求前及可中断单元间）和 `AuthorizeTx`（在实际写入的同一 SQLite 事务内读取当前权限）。权限查询不是权限快照；事务冲突必须整笔中止，重试须开新事务并重新鉴权。禁止把事务外 Authorize 当作写入 fencing，也不得把数据库授权检查宣传为可追回网络请求。受限补充及撤销归下述 enrichment；清理独立授权规则见下述显式清理契约。

### 安全补充与持久撤销

`enrichment.Service` 是网页管理与 MCP 共用的同步应用能力，不接受调用者自由填写文字事实，不涉及 LLM。按识别补充（`EnrichIdentified`）在识别的写事务内执行；作者校正（`CorrectAuthors`）与封面改善（`ImproveCover`）把字段证据应用到系列并留收据（`applyEvidence`），确认证据的决定在同一写事务内重读：作者校正重读系列已识别来源的证据，封面改善重读当前封面资格。每个系列独立事务内重读实际资料库、当前值与锁，并调用 `AuthorizeTx`（网页主语检查当前管理员及非强制改密状态）；实际元数据、统计和完整操作收据一起提交，失败回滚，不带旧授权自动重试。协议不参与 SQL。

作者组以整组比较，其他仅比较所选字段；锁定任一所选字段或相关预期值不一致，整项 conflict，无关字段变化不阻止。

操作 ID 与扫描 run_id 分离；版本化收据持久保存真实用户/凭据身份、系列/资料库、时间、前后状态、每字段来源快照与短理由、评分原值/尺度/公式及 changed、no-change、conflict 或实际存储失败结果。请求键是同一用户/凭据内跨补充与撤销共享的 1–80 可见 ASCII 字符命名空间；相同键和相同载荷返回原收据，`replayed=true`、`applied=false`，不重做；换载荷拒绝。授权拒绝、非法输入和不可用错误不伪造已持久化收据。

持久请求摘要归 `enrichment/digest.go`：每个命令一份冻结的命令专用 V1 形状，字段与顺序不变，不序列化可扩展的响应 `State`。撤销仅固定 request_key、operation_id；作者校正、封面改善与作品群关系各以前导判别符区分，期望作者组按精确 name/role 排序去重。库里留着的、现已不存在的命令摘要同在命名空间里：同键换命令即为换意图，拒绝。新增可选摘要字段只在确有新意图时编码，旧意图字节不变；不能保持此不变量就另定带判别符的命令，不重定义 V1。不自动匹配多个历史 hash，不按旧收据猜测请求语义，无数据库迁移或摘要回填。收据旧 before/after 缺少 authors 时按缺失解码，不伪造当时作者，也不撤销未记录改变的作者组。

`Get`、`List` 重查实际目标当前 read 权限；MCP 必须指定系列，网页管理员可查全局。降序持久 sequence 游标，默认 20、最大 50，每页预算内完整返回收据，不截断单条。目标已删除的历史仅网页管理员可查。agent 凭据不能撤销所有者网页会话留下的收据，也不能撤销跟随一条**当前**由所有者确认的识别的补充收据（用户决定，识别的确认者经 `WithOwnerConfirmed` 端口在撤销事务内读取；端口缺失时一律拒绝）。两者都报 `ErrOwnerOperation`，在实际目标授权之后判定，不泄露存在性；协议层提示改为上报。人确认的识别与它带来的补充、所有者的撤回因此不会被 agent 倒回；其余 agent 收据不分出自哪张凭据，照下述规则可撤销。`Undo` 仅恢复原 enrich 收据实际改过的字段（关系收据按「作品群关系收据」的规则撤销），在同一写事务重查当前权限、锁及原 after 值；整组标签/链接变化拒绝覆盖，无关编辑保留。成功撤销是独立不可变收据并关联原 ID；已撤销或无实际变更返回 no-change，冲突不半恢复。撤销材料无自动到期；仅显式清理可丢弃恢复保证，未清理材料重启后仍可查询和符合条件地撤销；外部调用、扫描与普通提案语义不改变。

撤销写入的常规存储错误在同一已授权事务的 savepoint 内整体回滚，再提交 `kind=undo`、`outcome=failed` 收据；保留原操作关联、真实身份、请求键及意图摘要，before/after 均为本次尝试前状态，所有 changed/applied 为 false，不标记原操作 undone。结果理由不保存 SQL、触发器诊断、路径或密钥。同键同意图重放此失败收据而不再写入，换意图拒绝；不同键仍可合法撤销。失败记录不另开事务，不在回滚与记录之间让并发成功被旧失败遮盖；授权拒绝不进入尝试审计。savepoint、日志插入或提交自身失败时返回不可用错误，不承诺收据已持久化，也不宣称元数据已变更。

### 按识别补充

`EnrichIdentified` 在确认识别的调用方写事务内执行，不论确认来自 agent 还是所有者；在那里重读系列当前值与锁、重查 `metadata_write`，补充与识别一起提交或回滚。它按系列现有**全部**识别结论的来源快照取值，逐字段跳过锁定与非空的字段，不把整个系列判为冲突：

- 文本字段（标题、简介、出版社、状态）按来源优先级取第一个有值的，只填空。优先级来自配置 `identification.source_priority`，默认 Bangumi > AniList > MangaDex > MyAnimeList > Comic Vine；未列出的来源按默认顺序接在后面，未知键在配置校验里报错，修改即时生效。标题取来源的 Title，为空时取原名，Bangumi 的 Title 就是中文名、没有时回落原名。状态经归一化，认不出或为 unknown 算无值，继续看下一个来源。
- **标题占位例外**：`seriesmeta.TitlePlaceholder` 认定当前标题仍等于目录名时，那是扫描生成的占位值，替换为来源标题并保留锁，重扫不会改回；与目录名不同的标题受保护。收据记 `placeholder_title`，撤销可以越过标题锁恢复目录名，锁照旧保留，别的锁照常拦撤销。
- 评分只在缺失时按 `seriesmeta.EnrichmentRating` 生成：所有已识别来源的有效站点评分换算十分制后等权平均，保留原始分数、尺度与公式。新来源的识别到达时，当前评分若仍是公式结果且没被改过（它的来源记录指向一张带公式、实际改过评分的收据，记录值等于当前值）就重算；人工编辑不写来源记录，值一变就不再重算。
- 来源链接取所有已识别条目的并集，只追加，链接名用来源显示名；同 URL 或同名（不区分大小写）的链接已存在就不加。
- 作者按角色补空（用户决定）：系列已有的角色不动，每个缺少的角色取优先级最高、给出该角色的来源的作者。角色去首尾空白、不区分大小写比较，系列现有作者里没有角色的条目不占任何角色。
- 标签按下述标签策略只追加系列还没有的。封面不随识别变化。
- 每个写入的字段都写字段来源记录，指向本次收据：扫描据此保留它们（`seriesmeta.SourceBacked`，用户决定扫描保护带来源记录的值），agent 的改正也只认这些记录；不写来源记录的补充值会被下一本带 ComicInfo 的新书冲掉。
- 同一事务以 `proposal.SupersedePending` 把该系列全部待审提案逐条经 pending CAS 结案为 `superseded`（ADR 0011）。
- 收据仍是 kind `enrich`，查询、撤销、清理全部沿用；`identification{entries, placeholder_title, superseded_proposals}` 记下所依据的条目与结案的提案。每个字段的证据只留该字段用到的来源值与条目身份，不存整份快照，六万个系列各留一张收据时体积因此可控。

标签策略取自配置 `identification.tags`，修改即时生效；三项都是 0 取默认值、负数关掉对应过滤，默认值写在 `config.example.yaml`，模板与代码默认值一致由 config 测试守卫：

- 各已识别来源的标签按来源优先级取并集，投票类来源（`metadata.TagsAreVoted`，目前只有 Bangumi）内部按票数从高到低。`min_votes`：投票类来源的标签要有一个来源让它达到票数阈值才通过，拼写取这个来源的写法；其它来源的标签是来源自己维护的分类，不看阈值。Bangumi 快照有标签而缺票数时按票数未知处理，阈值开着就不取它的标签，其它来源照常；证据包刷新或重搜后就带上票数。
- `blocklist` 屏蔽媒介、地区、年份、连载状态与个人状态等噪声词。条目与标签都按 `database.NormalizeSearchText` 规范化后比较；前后带 `/` 的条目是匹配规范化标签的正则，编译不过的在配置校验里报错。不写取默认列表，写成 `[]` 表示不屏蔽。
- `max_per_series`：一个系列从来源至多选这么多个通过前两道的标签，系列已有的也占名额，只追加还没有的；同一组来源重复补充结果不变，新来源到达时按全部来源的并集重选，已追加的标签不删。与系列已有标签去重同样按规范化比较。`tags` 锁住时跳过。

### 识别撤回与字段改正

`RetractIdentified` 在撤换或撤回识别的调用方事务内，逐字段撤回被撤条目带来的值。字段只在它的来源记录指向一张仍有效的识别补充收据、当前值仍等于那张收据写入后的值时才撤（撤销同款期望值校验：锁会拦住，占位标题例外）；从那张收据往回，沿「之后没被改动的连续识别补充」回到链首的写前值，链上任一张收据引用了被撤条目就恢复到它。所以分几次识别的多来源系列，撤掉其中一个来源时，它参与过的评分、链接与作者也一并撤回，其它来源的值随后由重新补充算回；之后被人或别的写入改过的字段保留。撤回收据是 kind `enrich`，以 `identification.retracted` 记下被撤条目，可以撤销。

`CorrectField` 在识别模块的事务内替换一个未锁、仍等于来源记录值的标量（可改正的字段与拒绝边界见 `mm-identification`）。收据带 `correction{field, replaced}`，保存被替换值原来的来源记录，改正值写自己的来源记录（source 为 `agent`）。Undo 恢复原值并经 `seriesmeta.RestoreFieldProvenance` 原样放回那条记录，恢复的值重新受扫描保护、可再改正。

### 作品群关系收据

`AddRelation` 在两个都可写的系列之间添加一条关系：类型取 `organize.RelationTypes`，语义是「target 是 series 的 relation_type」。原因、收据与 `organize.AddRelationTx` 的增删及待重建标记同事务提交，提交后安排作品群重建，ADR 0012 的持久待重建标记兜底。两系列之间任一方向已有关系时不改它，收据为 no-change 并报告那条关系。收据 kind 为 `relation`，before/after 是系列当时未变的元数据；请求键与补充、撤销共用命名空间，摘要以 `command` 判别。撤销只在关系的 id、方向与类型都与本次添加一致时删除，否则记 conflict、关系原样保留；撤销时重查两端系列的 `metadata_write`，已删除的一端跳过。不提供删除既有人工关系的能力，所有者在系列页删关系。

### 归档自动封面改善

`ImproveCover` 接受本系列已授权归档的 book_id、一基 page 与最多 1000 字节的质量比较短理由，收据的 `CoverSelection` 记 quality_compared=true。不接受 URL、任意宿主路径或上传字节，不增加远程取图/SSRF 边界。封面单独成一项操作，不带文字字段。质量优劣由 agent 比较和显式选中，服务端不伪称理由就是客观质量证明，也不以分辨率自动替换。

目标是目录按 sort_number/name/id 选中的首个现有封面书，不是任意书或缺封面的补图入口。`State.cover` 保存 book_id/path/locked/automatic；初始仅认可扫描器 path/mtime/size 自动键，或本能力保留的归档封面材料键。内容寻址的人工手选/上传键即使后来解除锁也不合格；当前 book.cover_locked 或系列 cover 锁均保护。准备后在实际写事务内重读系列/库、源书归属、当前目标封面、锁和当前 user ∩ credential ∩ library ∩ metadata_write；预期值不符整项 conflict，无关字段不阻止。 准备前先检查当前授权、源书身份及页码，再比较封面状态、锁和自动来源；已发现的业务冲突不读取或准备无用图片，交由最终当前授权事务保存永久 conflict 收据，即使其间状态恢复也不执行该请求。缩略图读取后、材料准备前再次检查；准备后的事务检查仍为最终权威。非法命令/页码、越界源书及权限拒绝不是可查询 conflict；同键重放已提交冲突，换意图仍拒绝。

图片准备沿用 `delegated.PageThumbnails` 的 read 交集、内容准入/句柄与严格预算（384 边、JPEG 65、96 KiB、不放大，源字节/像素与 RAR 预算仍归 mm-bookcontent/mm-images）。这是有界替代封面，不提供任意原图或阅读分辨率。另有两个可取消的整项准备槽，约束旧图读取/验证和准备文件的并发。同步请求的取消贯穿准备和随后的事务，IO 等待取消归还内容读资格及图片/准备槽。取消与 COMMIT 竞争时仍须按原键查询持久结果，不以断连断言未提交。当前旧图片原字节有界验证后保留，来源 book/page、比较理由与旧/新材料键进入持久收据。

#### 文件与 SQLite 故障一致性

选定 **不可变资源先准备，SQLite 引用后发布**，不是“数据库事务等于跨存储事务”。`covermaterial` 在缩略图根的相邻 `<thumbnail-root>.metadata-covers/metadata-covers/` 私有目录生成随机唯一文件，以 O_EXCL 创建，写入、Sync、Close 全部成功才允许进入事务。资源永不覆盖；准备未修改旧图或当前引用。封面引用、派生统计、收据与材料引用在同一个 SQLite 事务提交，常规写入错误由同一授权 savepoint 回滚再记录 failed。没有提交后必须执行的 rename、复制或文件发布步骤。

公开 metadata-covers 键是虚拟键，不是普通缩略图树内的真实目录。按书 ID 的 cover 路由从已提交 book.cover_path 读取；按文件名的 thumbnail 路由只有当前书或已提交材料引用才可读虚拟资源。普通文件读取限定在缩略图根，不能通过父路径、符号链接或 Windows 文件名别名进入私有根。这样准备文件即使已存在，也不能经旧的按文件名路由提前发布；不另建图片宿主。普通阅读、扫描和人工换封面的策略不变。

- 获取、解码、写入、Sync 或 Close 失败：不开始元数据切换；文件写失败仅尝试删除该调用独占的新文件。不回滚外部请求或 CPU/网络费用。
- 字段/锁/授权冲突、DB 写入/材料引用发布/日志失败：无封面半提交。常规写失败保留既有 failed 收据语义；事务/日志不可用不伪造持久收据。
- COMMIT 失败：返回不可用，资源保留；不能据错误盲删可能已经提交的资源。客户端查询或用原请求键确定持久结果，不能把连接错误解释为可安全重做。
- 成功提交后进程退出/重开：无需文件发布恢复，只读取同一持久引用；未提交准备或崩溃遗留文件没有公开引用，保持不可读。承诺进程/请求故障与服务重开的一致性，不宣称对外部删文件、损坏磁盘或平台不提供的目录元数据断电持久性作绝对保证。

旧图使用独立不可变材料键，不依赖可能被普通缓存清理或人工覆盖的原文件名。Undo 在同一事务比较原 after 封面/当前锁，恢复保留的旧图；后续人工封面变化冲突，无关字段保留。撤销本身也有 immutable receipt 和材料引用；原材料默认不按时间到期。

#### 显式清理撤销材料

`Cleanup` 是网页管理员与 MCP 共用的单项应用用例，仅接收 operation_id 和 request_key；不接受文件名、路径、来源 URL 或全库清扫条件。MetadataWrite 不隐含 Cleanup。每次命令、每个回收单元在实际 SQLite 事务内检查当前管理员（非强制改密）、真实系列当前库与历史库一致，以及委托凭据的当前 user ∩ credential ∩ library ∩ cleanup；MCP 不允许清理已删除或已迁库目标，网页管理员可清理已删除目标历史。猜测操作或清理结果标识不能绕过作用域。按 mm-adr-0016 草案已批准的票据边界，获授权 agent 自主清理，不增加逐批人工确认，也不允许自授或扩大权限。

单项最多考虑收据的两份不可变材料，不遍历目录。默认普通缓存清理、运行历史 retention、重开与时间流逝均不触碰撤销材料。没有全库孤儿回收器：完全准备但从未形成收据的孤儿保守保留；失败/冲突收据明确归属的准备材料可由显式命令清理，须走同样引用保护。活跃准备生成唯一新键，不被目录枚举或按年龄删除；当前材料准备读取与引用切换竞争时，最终事务 CAS/授权和持久 fence 仍约束发布。

清理采用 **先持久隔离、后有限回收**：

1. 当前授权事务中移除目标收据的 before/after 恢复快照、完整来源快照、选择与旧/新材料键；保留 ID、真实身份、系列/库、时间、kind/outcome/parent、字段名及短理由等最小审计。设置 undo_unavailable 与 cleaned_by，删除仅该操作的多对多保留引用。原 request_hash 不变，不回填或重算 08/09/10 意图。
2. 同一事务检查所有 books、series_stats 和其他 metadata_cover_materials 的引用；共享或当前使用的图片记 protected，不删文件。不依赖范围内引用推断全局无引用：其他系列/资料库引用也保护。仅确证无引用的规范随机材料键建立永久 tombstone，并保存 pending 清理收据，然后提交。
3. 持久 tombstone 的数据库触发器拒绝 books、series_stats 和保留引用新增/切换到退休键，包括普通封面写入和并发 Undo；Undo 先读到清理状态时返回 outcome=unavailable/applied=false，不把缺材料当完整恢复。Undo 先提交时，其保留引用及恢复后的当前封面保护材料。事务失败整体中止，不解除其他操作引用。
4. 每个文件前再过检查点和当前事务授权，使用 os.Root 限定私有根，仅允许完整规范随机键，拒绝根/目录/叶符号链接与非普通文件，不递归、不删除藏书或普通缓存文件。文件成功/失败逐项持久化，complete 表示快照清理及可回收单元完成，不表示 protected 文件已删；partial 明示文件失败且恢复保证已丢失。

数据库与文件不是跨存储事务。标记提交前失败不丢弃恢复材料；标记后取消、崩溃或结果写入失败可留下 pending 与隔离文件，不能谎报全部完成。仅当前获权的原键重放可继续 pending；文件已不存在视为幂等回收。终态 partial/complete/already-cleaned 重放其持久结果，不悄悄重试失败、刷新权限或清理其他 scope。已被保护而后来失去引用的材料及终态失败文件允许保守残留，没有自动追扫或承诺零残留。外部删除/损坏、配置根移动、断电/目录元数据持久性不在 SQLite 提交保证内。

清理使用独立 `(user,credential,request_key)` 命名空间与显式 V1 intent JSON（version、request_key、operation_id）摘要，不序列化响应 State/Operation，不改其它命令摘要。相同键不同目标拒绝；不同键再次清理已丢弃快照的操作返回 already-cleaned。`GetCleanup` 只读本人凭据的当前获权结果；网页 `InspectCleanup` 仅当前管理员可查，包括已撤销凭据的最小结果。清理审计不保存令牌、SQL 诊断、宿主路径或模型推理。

`StartCleanup` 为 1–20 个显式同库 operation/request_key 对创建共享 `Runs.Start` 运行，经同一个 `PrepareRun`/Checkpoint/Cancel 生命周期；不新建 goroutine 宿主、常驻 janitor 或重启恢复配方。排队撤权阻止启动，每项及文件前重查当前授权；已完成项不回滚，余项未处理，逐项结果按请求键查询，历史裁剪不删清理收据。断线不取消已接纳运行。批次重试可创建新 run，但已完成项只重放原效果，不提供批次 exactly-once 或批次原子性。单项同步命令有界且合并入口取消；断连与隔离提交竞争须按原键查询，不推断尚可恢复。

`InspectCleanup` 对 pending 结果可投影 `retry_request_key`：仅原网页执行者本人、当前 cleanup 授权通过、存储键仍符合原 printable ASCII 1–80 字节格式且独立 V1 digest/operation_id 匹配时提供。此字段不是凭据、不持久覆盖原意图；其他用户/委托凭据的结果不转移 retry namespace，仍须原执行者当前获权后原键续办。既有键、摘要与隔离状态不迁移或重写。

### 目标系列作者校正

`CorrectAuthors` 以系列当前整组作者为期望值；`State.authors` 是精确 name/role 身份对的整组快照，忽略顺序与重复，不隐式折叠大小写、空白或不同角色。`corrections` 明确列出 from/to 身份对与非空短理由（最多 50 条）；from 必须属于期望作者组，to 必须出现在该系列已识别来源的快照署名里（`Authors` 读出同一份证据）。重复 from、自映射和目标同时被移除的矛盾映射拒绝。多个别名可归并到一个已存在的身份；同名不同角色仍是不同身份。不接受无来源的新作者事实，不做全库合并；没有已识别来源的系列不能校正。

这是成员保留规则的获准例外，只替换显式 from 关联，其他成员保留。作者来源与校正短理由保存在字段审计，前后组留在同一持久单系列收据中，不存内部推理。提交与 Undo 均在实际写入授权事务检查当前资料库、能力、作者锁及整个组；其他任一关联变化冲突，无关字段不阻止。写入失败整体回滚；Undo 恢复旧关联组，失败收据和重开行为沿用既有契约。共享身份的持久写入归 `mm-seriesmeta` / `mm-database`。

### 提案裁决收据

裁决过已有提案的收据带 adjudication：proposal_id、原命令 mode、短 reason、当时 status 与 accepted；当前没有命令产生它，相同键永久重放原收据。提案生命周期以 pending + 持久接受标记、applied、supplemented_closed、rejected、superseded 区分结果，`Accepted` 事实投影归 mm-proposal。

Undo 仍是实际改动字段的独立单系列恢复，不恢复提案状态或字段行，也不清除接受历史；已恢复字段的最新来源记录仅在仍由原操作写入时移除（升级前未记操作的记录按原提案认领，兼容回归归 `TestProductionLegacyAdjudicationUndoReclaimsOwnProvenance`），不伪造未知的更早来源。原收据及来源/理由保持不变。普通人工 Apply/Reject、集合替换及 fill_empty 语义不改。

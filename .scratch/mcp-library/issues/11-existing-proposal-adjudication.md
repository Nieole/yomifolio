# 11: 裁决已有提案并关闭剩余差异

**What to build:** agent 可在受保护策略下处理已有提案，补充获准内容后放弃其余差异；用户能区分这种结果与全部拒绝，已成功应用的内容不被撤销，终态提案不能被继续写入。

**Blocked by:** 09 校正所选系列的作者关联。

**Status:** ready-for-agent

- [ ] 读取和应用已有提案时执行当前用户、凭据、资料库及元数据写入授权，复用已交付补充、标签和作者策略，不借普通提案的整组替换语义覆盖受保护内容。
- [ ] 提供补充后关闭剩余差异的完整操作，确定可持久区分的状态或呈现；网页与 MCP 可分辨全部拒绝、部分应用尚待裁决和补充后关闭。
- [ ] 关闭或拒绝不撤销先前已应用字段；单系列实际变更继续产生可追溯记录及符合条件的撤销，而非把提案状态回退当作内容恢复。
- [ ] 严格遵守 mm-adr-0011，在实际写入事务中重读待裁决状态、当前值、锁和已消费字段；终态竞争失败不提交元数据、提案字段或来源沿革。
- [ ] 并发部分应用不得重复消费字段，重放和关闭竞争有明确公开结果；不改变既有人工提案使用方式。
- [ ] 从生产服务验证旧提案输入、作者保护、成功后关闭、先拒绝后应用及部分应用竞争，保留现有真实事务回滚守卫；网页呈现不误报为全部拒绝。
- [ ] 后端与前端门禁及受影响生成物检查通过，更新裁决长期契约但不削弱有效 ADR。

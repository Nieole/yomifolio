# 12: 按本次额度调用内部 LLM

**What to build:** 具有内部模型能力的 agent 可转述用户对本次操作的调用次数额度，使用程序已有 LLM 来源辅助检索与整理；服务端累计用量，耗尽停止模型调用并汇报，非模型工作仍可继续。

**Blocked by:** 07 检索多来源候选并形成有依据的提案。

**Status:** ready-for-agent

- [ ] 内部 LLM 必须同时满足当前用户权限、凭据独立模型能力及本次明确次数额度；缺少任一条件均不调用，其他获准查询仍可使用。
- [ ] 按 mm-adr-0016 草案记录的已选边界，接受 agent 转述额度，不新增受信任人工审批渠道，也不把计数当作独立用户批准证明；agent 声明不能扩大凭据权限。
- [ ] 明确操作归属及额度记账契约，服务端跨请求、并发调用和断线重连累计，不得通过重复声明、分拆请求或重试重置已经使用的额度。
- [ ] 确定失败调用、重试及服务重启时的计数语义并测试；不因恢复或重放静默重新发送付费调用，不冒充可以准确限制货币成本。
- [ ] 每次实际调用前重新鉴权，安全检查点服从撤权；额度耗尽不再发起模型请求，返回实际用量和未处理项，允许非模型操作继续。
- [ ] LLM 可辅助身份判断，但生成分数不参与综合评分，不保存内部推理，不将未解决歧义写入系列。
- [ ] 生产服务使用可控模型替身验证无额度、无能力、并发耗尽、跨请求和重启记账、撤权及部分工作继续；不用真实计费验证限额。
- [ ] 后端门禁及受影响契约生成检查通过，明确记录用量保证与委托信任的区别，ADR 不因实现者自行判断而转 active。

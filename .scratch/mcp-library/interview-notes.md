## 已确认的访谈边界

- 服务约 10TB 漫画藏书的按需整理，减轻逐条确认来源候选的负担。agent 只按用户指令临时接入，不建立元数据待办、常驻 agent、扫描后自动接手或专门维护状态机。
- 按资料库、加入时间、缺失字段组合筛选或指定系列，分页读取系列、书目及本地识别线索。可读目录名、文件名、ComicInfo、封面和少量受限书页缩略图，不开放任意文件读取或整本归档下载。
- 搜索现有可用多来源并读取详情；agent 综合判断同一系列及版本，不把 confidence 当作身份匹配概率。身份冲突未排除时报告用户，不堆积未定候选；确认后才形成待写入提案。
- 允许按字段综合不同来源，保留字段来源及简短、可核查的判断摘要，不保存模型内部推理。
- 补空描述，保留非空值及字段锁；内容标签筛选后追加，不删除已有成员，不引入个人标记与噪声。作者可在所选系列内追加、归并别名及校正角色，不改共享作者行、不影响其他系列、不做全库归并。
- 补来源链接；只补缺失评分，来源站点评分统一十分制后等权平均，一个有效来源即采用其值。保留原分数、尺度、公式，不混入个人评分或模型自评。
- 可改善自动封面，保护手选、上传封面。单系列操作的文字与封面先准备再一起生效，全部成功或不生效；外部请求及费用不可回滚，多个系列允许部分成功。
- 支持提案读取、应用与裁决，补充后可关闭剩余差异，须区别于全部拒绝且不撤销已提交内容。终态后不得继续写入。
- 写入与撤销按涉及字段检查当前预期值，无关字段变化不阻塞；标签和作者分别按整组检查。后续修改或当前字段锁冲突时不强行覆盖。
- 发起必要扫描，查询、等待和控制授权内运行；耗时操作返回运行标识，客户端断线不取消，可重连查询。不得将此推导为进程重启自动续跑付费操作。
- 同时支持 Streamable HTTP 及连接正在运行服务的 stdio 辅助进程。辅助进程不直接打开数据库，不组装第二套运行时。
- 管理员网页统一签发、限制和撤销用户关联凭据；按资料库与查询、元数据写入、扫描控制、内部 LLM、清理能力限制，实际许可受当前用户权限交集约束。普通用户不因凭据取得原本没有的写入权，不改变现有网页目录读取权限。
- 撤权后阻止相关排队工作启动，运行中在安全检查点取消，写入与内部模型调用前重新鉴权。修改密码撤销用户 MCP 凭据；已提交系列不自动回滚，已发请求及费用不保证追回。
- 显式允许局域网明文 HTTP，接受内网凭据截获风险；公网 HTTPS。stdio 上游同样适用，不能因辅助进程本地运行就豁免远端明文连接。
- 内部 LLM 无本次明确额度不调用，服务端跨请求累计调用次数，额度耗尽停止模型调用并报告，其他操作可继续。允许 agent 转述额度，不将服务端计数当作独立核验过的用户批准。
- 按系列操作保存前后状态和必要旧封面，默认不自动清理。清理独立授权，获授权 agent 可自主执行、不要求逐批人工确认；保留最小审计、在用图片和藏书文件，明确清理后不再保证可撤销，agent 不得自行扩权。
- 网页设置提供管理员凭据管理、变更查询、撤销和手动清理，不新增独立管理命令。合集与个人阅读数据不是本 effort 核心，不包含文件删除、搬运及系统管理。

## 仓库核查事实

这些是实施须复核的代码事实，不是新增产品授权：

- internal/proposal/SPEC.md 与 internal/seriesmeta/SPEC.md：fill_empty 对集合按整组补空，ApplyProposal 对所选集合执行替换；不能直接当作已支持追加及作者校正。SaveManual 可改锁定字段，AppendScanAssociations 忽略集合锁并吞掉错误，都不能直接作为受限 agent 写入器。现有网页、扫描和普通提案语义须保留。
- internal/proposal/queue.go 的 Queue 在没有有效未锁差异时不保存候选，还可能复用已有提案；入队不等于无条件保存本次匹配判断。现有部分应用保留未处理差异，Reject 不撤销已应用内容；补充后关闭的可区分语义和依据持久化须明确承载。
- internal/database/schema.sql：作者身份按 name 与 role 组合唯一，角色属于共享作者行而非系列关联。校正应调整关联而非修改共享行。当前字段来源只存每系列每字段最新状态，不是追加式、可撤销历史。
- internal/metadata/provider.go 的 SeriesMetadata 与 internal/proposal/fields.go：候选可携带封面、来源链接等，但不代表提案全部支持；当前提案字段为 title、summary、publisher、status、rating、tags、authors，不能凭原始候选 JSON 宣称新范围已实现。
- internal/api/auth_controller.go 与 internal/database/users.go：现有 admin/regular 角色，不具备通用独立 API 凭据或用户级资料库授权。普通用户现可读取全部目录，查询过滤不是权限隔离；新协议不会自动继承 HTTP 脱敏与访问守卫。
- internal/task/start.go 的 RunSpec 在受理时支持 ValidateAccess，但执行上下文与请求分离、不带凭据归属；请求断开或网页会话撤销不会自动取消后台运行。
- architecture.md、internal/bootstrap/SPEC.md 与 internal/api/host.go：bootstrap.Open 组装生产资源，HTTP 经显式能力注入；新协议不得复制运行时或直读数据库。内容访问须正确释放句柄，不能把归档解析器大条目上限当作响应预算。

## 测试接缝与未选工程细节

用户确认以生产组装的完整服务为主接缝：通用 MCP 客户端和网页管理 HTTP，真实临时 SQLite、资料库及图片，仅替换外部元数据和 LLM；另做 stdio 真实进程烟测、少量网页交互及既有并发与资源释放回归。现有 bootstrap 测试可复用，但 MCP 客户端、stdio 测试设施和来源注入尚须补齐。首版不以 Claude Code、Codex 或 ThinkRail 特定交互兼容性作为门禁。

SDK 与标准授权兼容性、工具 schema、分页和图片限额、管理 API、操作标识、重试幂等、跨请求额度和进程重启行为、文字与图片故障一致性、撤销存储归属、关闭剩余差异的表示仍须工程核验，不得在拆票时冒充访谈已选定。若产生新的产品或安全取舍，回到用户确认。

官方文档及 GitHub 原始文档抓取被当前网络安全检查拦截，未绕过；尚未完成标准兼容性核验。

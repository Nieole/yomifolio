# 03: 书宽松匹配与全局精确命中优先

**What to build:** 读者按书名称、元数据标题或所属系列找到书；全局中系列与书按真实命中依据统一排列，不再固定书先系列后，也不会因大量归属书而掩盖更直接的命中。本票交付可验证的统一首批结果，为后续继续加载提供完整排序键。

**Blocked by:** 02 — 系列宽松名称匹配与旧库升级。

**Status:** ready-for-agent

- [ ] 书自身名称、元数据标题采用 02 的同源宽松匹配；名称和标题分别匹配。仅所属系列命中的书仍可返回，不扩大到作者、标签或路径。
- [ ] 书新增、改名、元数据更新、删除、旧库升级、失败重试和维护重建均维护一致的归一化投影与两类索引；直接从原有旧版本升级以及从 02 的中间版本升级都能得到完整结果。
- [ ] catalogsearch module 按正式规格统一排名：自身精确命中、自身子串命中、仅所属系列命中。所属系列精确不等于书自身精确；多个来源命中同一书时，取最佳排序键且仅返回一次。
- [ ] 同层依次按起始字符位置、额外字符数、类型与持久标识组合排序。完整排序键只使用有界数值和唯一身份，不含完整标题、名称或其字典序；字符计数不按 UTF-8 字节。
- [ ] 全部模式按同一顺序选择整批结果，资料库列表原有排序不变。候选裁剪和去重必须保证统一首批完整性，不能截断原始重复来源后导致漏项或缺额。
- [ ] 不比较不同语料的原始 BM25，不按每批最大分数缩放后排序；兼容 score 按三层分别为 1、0.5、0.25，空批 max_score 为 0。全局界面隐藏分数，保留名称、封面、类型与导航。
- [ ] 沿用现有检索范围及 title 作为 book 的别名；不扩大权限或改变读者阅读视图。首批采用正式规格的统一默认批量；后续结果可达性和新分页响应由 04 完成。
- [ ] 通过真实 HTTP + SQLite 验证跨类型混排、各层及同层排序、同名同分、仅标题命中、多来源去重、大量归属书与直接匹配系列共存；对照完整预期排序的首批前缀，而非只断言各类型内部有序。
- [ ] 前端验证分数不再显示、系列/书导航正常；与 01 已完成的会话状态兼容，但不把 01 当成此票的实施前置。完成本票后端测试、格式/lint，以及涉及前端的测试、构建/lint和必要生成检查。

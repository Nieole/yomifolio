# 05: 搜索全链路验收与大库性能验证

**What to build:** 为读者可依赖的新搜索提供可复验的完整交付证据：真实入口上能一致匹配、按相关度找到首批之外的目标、可靠处理交互失败；旧库与协议客户端不回归，大库性能符合正式规格。本票是最终集成门禁，不替代前序功能票自带的验收。

**Blocked by:** 04 — 稳定游标与弹窗继续加载。

**Status:** ready-for-agent

- [ ] 从真实旧版本藏书升级，覆盖一次升级到最终版本以及经过中间版本的升级；在升级、增删改和维护重建后，从真实 HTTP 全局/资料库入口对照独立 oracle，再通过继续加载核对完整有序结果。
- [ ] 通过已确认的两处高层 seam 串联验证正式规格的全部用户行为；回归 OPDS/Mihon 真实总数与分页、资料库筛选和排序、读者权限，以及空输入、空结果、无效游标的兼容响应。
- [ ] 对实际搜索交互验证慢响应、失败/重试、切范围、关闭/重开、键盘导航、连按追加、长标题边界、游标失效重新搜索、本地化与可访问状态。执行真实浏览器验证并记录环境；若受限，明确未执行项，不用静态渲染冒充交互验收。
- [ ] 如已取得实际漏搜系列和关键词，补充精确回归并记录诊断依据；如仍缺样本，明确真实根因未复现，不取消已定义验收，也不声称本次已证实某项架构差异就是根因。
- [ ] 同机同 SQLite 设置冻结至少 20 万本书、2 万个系列的数据，覆盖短词/长词及稀疏/广泛命中；预热后每场景至少测量 100 次，记录 p50/p95、硬件、数据分布、页大小与缓存条件。
- [ ] 对新旧语义一致的查询，首批 p95 不超过旧实现两倍；新增宽松匹配场景独立报告。新实现深页 p95 不超过对应首批两倍，覆盖靠近末尾的页，排除累计重拉前页或隐蔽 offset 放大。
- [ ] 额外搜索派生数据升级回填耗时不超过同规模完整维护重建两倍，区分其他既有迁移开销；验证候选访问由索引驱动，不以每次全藏书归一化换取功能通过。相对预算是待执行门禁，不是已存在的测量结论。
- [ ] 执行全量后端测试、格式与 lint，以及前端测试、构建、lint；完成实际涉及的 SQL 与 TypeScript 契约生成和漂移检查。性能测量独立于普通单元测试，不增加脆弱墙钟断言。
- [ ] 修复本票发现的集成回归，预算失败时优化或显式调整正式规格，不得省略测量后宣布完成。交付证据区分通过、失败与未执行限制，不假定游标提供整次搜索快照。
- [ ] 将已实施结果同步到所属 module 持久规格、用户可见变更记录和连接函数维护限制；未实施或未验证项不得写成现有能力。不扩展到新检索字段、拆词、语义搜索或新引擎。

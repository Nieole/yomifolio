# 04: 稳定游标与弹窗继续加载

**What to build:** 读者可以在同一弹窗继续找到首批之外的系列和书，看到已加载数量与是否还有更多；追加失败不丢失结果，游标失效时能明确重新搜索。长标题不能让后续结果永久不可达。

**Blocked by:** 01 — 搜索等待、失败与旧响应隔离；03 — 书宽松匹配与全局精确命中优先。

**Status:** ready-for-agent

- [ ] 按正式规格扩展既有全局请求：默认 target 为 all，保留 series/book/title 别名；limit 默认 20、最多 100，针对混排整批。非法 target、非法/非正/超上限 limit 返回 HTTP 400。
- [ ] 使用统一排名后的 keyset 分页与 limit 加一探测，不执行全局完整 COUNT，不先对各类型截断再错误宣称后续不可达。需要多次底层读取形成一批时使用同一读事务。
- [ ] 游标绑定格式/排序版本、规范化关键词 SHA-256 摘要、规范化 target、有效读者身份、权限上下文摘要及完整有界排序键；摘要采用版本化规范编码，不携带无限长查询、标题或权限列表。
- [ ] 验证 URL 安全载荷的结构、类型、数值、版本及 8 KiB 上限；服务端生成的游标必须能被自身在同一限制内接受并续页。游标不是授权凭据，每次查询重新鉴权并在筛选后分页。
- [ ] 无效、过长或查询/身份/权限上下文不匹配的游标返回 HTTP 400 与稳定错误码 invalid_search_cursor，不静默忽略。只有输入分隔或宽度不同但归一化后相同的关键词可以共用游标。
- [ ] 保留 hits、total_hits、max_score、身份与既有 fields 字段，新增 has_more、next_cursor；hits 始终为数组，末页游标为空字符串。total_hits 仅为当前批条数，不是完整总数或累计数。具名响应与 fields 类型纳入既有 Go 到 TypeScript 生成和漂移检查。
- [ ] 弹窗保留全部/系列/书切换，显示去重后已加载数和是否还有更多；继续加载立即执行，同一查询代际只允许一个追加请求，成功后才推进游标。
- [ ] 普通追加失败保留结果、有效选择和未消费游标，可重试；游标失效显示显式“重新搜索”，禁用继续追加，由用户动作从首批重新开始，不静默混接新旧结果。
- [ ] 新查询、切范围、关闭或重置使旧游标和追加请求失效；取消无效的旧响应不能回写。追加去重并保持有效选择，键盘操作不越界。状态文案完成本地化及辅助技术支持。
- [ ] 同一静态数据集按任意合法批量走到末页，与完整预期集合和顺序一致，无重漏。至少覆盖书、系列都超过旧首批限额、跨资料库、全部/单类型、同名同分、空批及末页。
- [ ] 经既有元数据写入入口保存足以使完整标题游标超过 8 KiB 的标题并放在分页边界，证明生成游标仍合法且可续页、标题未截断、结果未丢弃；同时覆盖长但合法关键词的固定摘要绑定。
- [ ] 使用真实 HTTP 验证契约、权限、错误与兼容；前端组合测试覆盖连按、追加失败重试、重复响应去重、失效后重新搜索及过期追加隔离。协议分页和真实总数不被全局分页改动破坏。
- [ ] 明确游标不是快照：静态数据保证无重漏，并发增删改不承诺跨批完整性；前端去重不冒充快照保证。完成本票前后端门禁及契约生成检查，不把核心验证推迟到 05。

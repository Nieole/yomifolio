# 统一搜索匹配、结果可达性与搜索会话

Status: ready-for-agent

## Problem Statement

用户确定某个系列存在，却在全局搜索找不到，到对应资料库按名称搜索反而能找到。用户无法判断究竟是名称不匹配、结果被截断，还是搜索请求尚未完成或已经失败。

代码调查确认了三类割裂：全局与资料库的短词匹配路径不同；全局结果固定截断且不能继续检索，全部模式并未统一混排；搜索交互无法可靠区分等待、失败、成功零结果和过期结果。它们是需要修正的行为差异，但尚未取得真实故障样本，不能声称任何一项已经被证实为该次漏搜的根因。

## Solution

同一关键词对同一系列采用一致、可预测的名称匹配规则。忽略大小写、全半角宽度、空白和标点差异，保留连续子串语义与符号含义。

全局搜索按实际命中依据统一排列系列与书：自身精确命中优先于自身子串命中，后者优先于仅由所属系列匹配带出的书。用户在当前弹窗继续加载，直到浏览完全部可见匹配结果，不再被首批限额阻断。

搜索明确显示等待、失败和成功空结果，提供重试；切换关键词或范围后，旧结果立即失去交互资格。加载更多失败时保留有效结果。系列仍进入详情，书仍进入阅读，不改变权限或读者阅读视图。

## User Stories

1. As a 读者, I want 同一系列在全局与对应资料库使用一致的名称匹配规则, so that 我不必猜测哪个入口才能找到它。
2. As a 读者, I want 用系列原名查找系列, so that 元数据标题变化不会让原名失去检索价值。
3. As a 读者, I want 用元数据标题查找系列, so that 不知道磁盘目录名时仍能找到目标。
4. As a 读者, I want 用书的名称或元数据标题查找书, so that 可以直接进入想读的书。
5. As a 读者, I want 单字、双字与长关键词都可查询, so that 不必为了索引限制改写输入。
6. As a 读者, I want 大小写不影响匹配, so that 不必记住标题的字母形式。
7. As a 读者, I want 全半角宽度差异不影响匹配, so that 输入法差异不会造成漏搜。
8. As a 读者, I want 空白和标点差异不影响匹配, so that 可以用自然输入找到名称分隔方式不同的系列。
9. As a 读者, I want 数学等符号保留匹配意义, so that C++ 不会被误当成 C。
10. As a 读者, I want 只按宽度折叠而不额外合并圈号等兼容字符, so that 搜索不会超出可理解的名称规则。
11. As a 读者, I want 关键词归一化后仍按连续子串匹配, so that 空格不会悄悄变成拆词检索。
12. As a 读者, I want 名称与元数据标题独立匹配, so that 不会出现跨字段拼接出的虚假命中。
13. As a 读者, I want 空白或仅标点输入不会返回整个藏书, so that 无效输入不会造成大量无关结果。
14. As a 读者, I want 系列与书自身的精确命中排在最前, so that 能迅速找到明确输入的目标。
15. As a 读者, I want 自身子串命中优先于仅所属系列命中的书, so that 一个系列的大量书不会掩盖更直接的目标。
16. As a 读者, I want 仍能通过所属系列找到相关书, so that 不必知道每本书的独立名称。
17. As a 读者, I want 同一本书命中多个字段时只出现一次, so that 结果不会被重复条目占用。
18. As a 读者, I want 全部模式按统一相关度而非固定类型先后排列, so that 书和系列都能按匹配程度被发现。
19. As a 读者, I want 同名同分结果有稳定顺序, so that 继续加载时不会无故重复或遗漏。
20. As a 读者, I want 切换全部、系列、书三种检索范围, so that 可以缩小查找对象。
21. As a 读者, I want 在弹窗继续加载剩余结果, so that 超过首批限额的系列仍然可达。
22. As a 读者, I want 看到已加载数量与是否还有更多, so that 不会把首批数量误以为完整总数。
23. As a 读者, I want 加载到末页后明确知道没有更多, so that 不必重复尝试。
24. As a 读者, I want 不看到难以解释的相关度数字, so that 注意力集中于名称与目标。
25. As a 读者, I want 查询等待时看到明确状态, so that 不会把尚未完成误认为没有结果。
26. As a 读者, I want 失败与成功零结果分别表达, so that 知道应该重试还是修改关键词。
27. As a 读者, I want 首批失败可以重试, so that 临时网络错误不要求重新输入。
28. As a 读者, I want 新关键词或范围生效时旧结果不能被选中, so that 不会误开上一次搜索的书。
29. As a 读者, I want 过期响应不会覆盖新查询, so that 快速输入仍然可靠。
30. As a 读者, I want 关闭或重置搜索后旧请求不会回填结果, so that 再次打开时不会出现错误归属。
31. As a 读者, I want 追加失败时保留有效结果并能重试, so that 已找到的内容不会丢失。
32. As a 读者, I want 重复点击继续加载不会重复条目, so that 结果列表保持可信。
33. As a 读者, I want 键盘选择、回车和鼠标选择始终作用于有效条目, so that 查找过程可快速且安全地完成。
34. As a 读者, I want 点击系列进入详情、点击书进入阅读, so that 原有操作路径保持不变。
35. As a 读者, I want 资料库筛选与访问权限在搜索中仍然有效, so that 不会看到无权访问或不满足筛选的内容。
36. As a 管理员, I want 新增、改名、元数据更新和删除后搜索自动保持一致, so that 不必手动修复常规写入造成的漏搜。
37. As a 管理员, I want 旧库升级时自动完成必要索引回填, so that 不需要重新扫描藏书来获得正确匹配。
38. As a 管理员, I want 回填中断后能够安全重试, so that 不会留下标记完成但索引缺失的状态。
39. As a 管理员, I want 维护重建与增量维护使用同一名称规则, so that 重建不会改变搜索含义。
40. As a OPDS/Mihon 使用者, I want 原有分页与真实总数契约保持有效, so that 全局搜索的改进不会破坏协议客户端。
41. As a 读者, I want 无效的继续加载状态被明确拒绝并可重新搜索, so that 不会静默接到另一关键词的结果。
42. As a 管理员, I want 大库继续使用索引并有可复验的性能证据, so that 匹配更宽松不会换来持续全库扫描。

## Implementation Decisions

### Module depth 与职责

- 数据库 module 集中归一化、字段匹配、索引及升级维护知识，提高 locality；保留按场景的查询，不建立万能查询 module。
- catalogsearch module 持有命中层级、统一相关度、去重、全局排序与游标语义，向调用者提供有 depth 的查询 interface。HTTP adapter 不重复拼配排序，前端不按当前页重排来伪装全局排序。
- 搜索会话 module 持有查询身份、请求代际、取消、重试、追加及有效选择。消费者使用该 interface，不分别推断结果归属。
- 保留现有 SQLite 与 HTTP adapter，不为假想第二种实现新增 seam。遵循现有按完整功能组织查询、藏书事实与读者阅读视图区分的 ADR。

### 归一化与索引

- 对每个名称或标题独立应用同一确定性规则：Unicode 宽度折叠、规范组合 NFC、与语言环境无关的 Unicode case folding、删除 Unicode 空白及 Punctuation 类字符，最后再次规范组合。符号类不删除。不得用完整 NFKC 代替仅宽度折叠。
- 字符长度和位置均按归一化后的 Unicode 字符计算，不按 UTF-8 字节计算。查询与索引写入、回填、维护重建使用完全相同的函数及字符规则。
- 未提供的标题按空文本处理，不与名称拼接。归一化为空的查询返回空结果，不进入全匹配条件；只有空白的输入由前端作为未输入处理。
- 全局与资料库系列查询采用相同匹配谓词；是否通过索引加速不应改变命中集合。归一化后的长度决定短词 gram 与长词 trigram 路径，不能按原始长度选择。
- 将归一化函数注册到所有相关 SQLite 连接，含迁移、运行期、维护及测试连接；由触发器维护系列和书的搜索索引，覆盖所有实际写入，不只覆盖扫描入口。函数注册失败应明确失败，不能降级成静默漏查。
- 使用派生索引而不是每次对整个藏书逐行归一化。若排序需要读取归一化文本，数据库 module 自行持有可查询的派生投影，与索引同源维护，不让调用方重新计算或依赖 contentless 索引返回文本。
- 不修改原始名称与标题以适应搜索，不改变展示、磁盘路径或系列和书的身份。

### 升级与重建

- 通过统一迁移入口执行版本门控回填，显式替换受语义变化影响的旧触发器并重建两类索引及必要派生投影；仅创建不存在的触发器不足以升级定义。
- 成功完成回填后才记录新版本；中断或失败后允许重试。不将现有全库迁移描述为天然原子事务，也不以表非空判断回填已经完成。
- 正常写入、升级回填和维护重建必须对同一数据得到相同结果。升级需要一次性派生数据重建，不要求用户重新扫描归档。
- 外部直接写库的连接也需要支持该函数。此限制必须记录到面向维护者的文档，不能将原生 SQLite 工具写入失败当成搜索零结果处理。

### 统一排名与去重

- 每个候选匹配按以下层级升序排列：自身名称或标题精确匹配；自身名称或标题连续子串匹配；仅所属系列名称或标题匹配的书。不存在匹配则不返回。
- 同层依次比较：关键词在命中字段的起始字符位置、更小的字段额外字符数，最后用类型与持久标识的组合破同分。这样前缀及更紧凑的名称优先，书与系列采用同一规则。完整排序键只含命中层级、字符位置、额外字符数、类型及持久标识，不含原始或归一化的完整名称、标题，也不以完整字段字典序排序；避免现有无长度限制的标题放大游标。
- 一个结果从多个字段或来源命中时取其最佳完整排序键，并按书或系列的持久身份去重，再参与分页。所属系列精确匹配仍在归属层，不提升成书自身精确匹配。
- 类型仅为末级唯一键的一部分，不作为书优先或系列优先的分组规则。资料库列表原有排序不因全局相关度公式而改变。
- 不比较不同语料的原始 BM25 分数，不按各批最大分数重新归一化来排序。为保留旧数值字段，三种命中层级的兼容 score 分别为 1、0.5、0.25；max_score 为当前批的最大 score，空批为 0。这些字段不是完整排序键，前端不再展示它们。

### 全局请求与响应契约

- 沿用全局搜索 HTTP 入口，增加可选 limit 与 cursor。省略 target 时为 all；保留 all、series、book，以及旧 title 作为 book 别名。别名在游标绑定前规范化，非法 target 返回 HTTP 400。
- 每批默认 20 项、最多 100 项，限额针对统一排序后的整批，不是每类型各一批。不合法、非正或超上限的 limit 返回 HTTP 400，不静默扩大读取。
- 省略 cursor 表示首批。响应保留 hits、total_hits、max_score 及既有 hit 身份与 fields 字段，同时增加 has_more 与 next_cursor。hits 总是数组；空结果、空查询、仅标点查询也返回同一形状。末页 has_more 为 false、next_cursor 为空字符串。
- total_hits 为当前响应的条目数，保持“返回数”含义，不承诺完整匹配总数，也不是累计加载数。前端累计数量由当前会话已接收且去重的结果计算。
- 采用 limit 加一探测是否还有更多，不为了全局界面执行完整 COUNT。不得先截断各类型再错误宣称剩余结果不可达；候选裁剪必须能证明不会丢失混排后的后续结果。
- 将新增契约表达成具名响应与 hit fields 类型，纳入已有 Go 到 TypeScript 契约生成与漂移检查，避免前后端各维护一份松散形状。序列化字段名称及已有身份格式保持兼容。
- 无分页参数的旧请求仍能读取既有响应字段；全部模式改成统一排序的一批是本次有意行为变化，不保留旧的书先、系列后及每类型首批上限。

### 游标与读取一致性

- 使用无服务器会话状态的 keyset 游标，包含格式/排序版本、规范化关键词的 SHA-256 摘要、规范化 target、有效读者身份、检索权限上下文的 SHA-256 摘要、最后一个结果的完整排序键。摘要输入使用确定性的规范编码，不依赖字符串随意拼接；查询摘要绑定归一化规则版本。游标不携带任意长度的关键词、标题或权限列表。游标是定位信息，不是授权凭据；每次请求仍重新鉴权并在筛选后分页。
- 游标采用有长度限制的 URL 安全编码载荷；严格验证版本、字段、枚举及取值，输入上限为 8 KiB。排序数值采用明确的有界整数域；类型、版本及摘要采用有界表示。服务端生成的每个游标必须在同一大小限制内且能被自身解析并继续检索；这一性质不得依赖现有标题长度。不得截断名称、标题、关键词或匹配集合来满足游标大小。不得执行客户端提供的 SQL 或排序表达式。游标字段不需要泄露路径、密钥或源文件信息。
- 格式错误、版本失效或查询、身份、权限上下文不匹配时返回 HTTP 400，稳定错误码为 invalid_search_cursor，不忽略错误后继续返回另一批。关键词只有原始分隔或宽度不同、但规范化结果相同时，可以继续使用游标。
- 游标按完整排序键 seek，不依赖上一结果仍存在。需要多次底层读取才能形成一批时，使用同一读事务保证单批视图一致。
- 静态数据集必须无重漏；不保留整次搜索快照，不保证查询期间新增、删除、改名或修改元数据后的跨批完整性。前端按身份去重，不借此宣称并发修改下也无遗漏。
- 协议搜索共享归一化匹配语义，但继续保留各自的分页方式与真实总数；不强行切到全局游标或替换为当前批数量。其他协议排序保持其既有契约。

### 搜索会话行为

- 空输入为 idle；非空输入进入防抖等待及请求状态。保留现有约 300ms 防抖，重试和继续加载不额外等待防抖。只有请求成功且空结果才能进入无结果状态。
- 关键词、target、有效登录/连接上下文或开关状态改变时提升请求代际并取消旧请求；结果写入还需校验代际、查询归属及当前是否打开。不得仅靠取消保证安全。
- 新关键词或范围立刻清空旧列表与选择资格。关闭或重置使在途请求及旧游标失效；再次打开对保留的当前输入重新查询，不复用未验证结果。
- 首批失败显示明确错误与重试。普通追加失败保留条目、选择和未消费游标，重试同一批；同一代际只允许一个追加请求，接受响应后才推进游标。
- invalid_search_cursor 属于需要重新开始的失败：保留现有列表供查看，禁用继续追加并显示“重新搜索”；由用户动作从首批重新开始，不静默混接新旧排序。
- 追加成功按身份去重后扩展列表，保持仍有效的选择；新查询成功后按既有默认选择习惯选择有效条目。加载中、关闭、重置、无结果或错误导致无有效条目时，回车不打开目标。
- 隐藏无解释价值的 score 数字；呈现已加载数量、有无更多及等待、重试状态。保留既有封面、类型、名称、导航与键盘操作；状态文案遵循既有本地化方式，异步状态应可被辅助技术感知。

## Testing Decisions

### 已确认的测试 seam

用户已确认保留两处现有高层 seam，不新增测试专用生产 interface：

1. 真实 HTTP 查询入口配合 SQLite：对同一数据执行全局与资料库搜索、继续加载及协议查询；从真实升级/维护入口执行后再查询，验证实际持久化行为。
2. 前端搜索会话与弹窗交互：通过输入、切换、重试、追加、关闭和键盘动作验证状态与导航，使用可控请求完成顺序制造竞争。

interface 是测试面。测试断言外部可观察的命中、顺序、状态、错误及可达性，不断言私有函数调用次数、SQL 字符串或中间状态变量。数据库内部测试仅补充必要的故障注入、迁移覆盖与查询计划验证，不替代高层行为测试。

### 后端行为与升级

- 用独立的直接匹配预期值验证命中，而不是只比较两个可能一起漏查的入口。覆盖原名、仅元数据标题、单字、双字、长词及归一化后长度跨分支的情况。
- 覆盖宽度、ASCII 与非 ASCII 大小写、组合字符、空白、Unicode 标点、保留符号、圈号、空输入与仅标点；加入跨字段不应命中及“进击 巨人”不命中“进击的巨人”的反例。
- 覆盖全局混排层级、同层排序、同名同分、多个匹配来源、书去重；让大量归属书与直接匹配系列同时存在，证明系列没有被错误挤掉。
- 构造跨资料库且书、系列均超过旧首批限额的数据，走全部、系列、书直到末页，与完整预期有序集合一致；覆盖不同合法批量大小、首批与末页。
- 通过既有元数据写入入口保存长度足以使完整标题游标超过 8 KiB 的标题，并让其成为分页边界。验证服务端生成的游标仍在上限内、能被自身接受、后续结果无重漏且原始标题未截断；同时覆盖很长但合法的关键词，证明摘要绑定不放大游标。
- 验证 target 别名、无效 limit、响应空数组与兼容字段、无效/过长游标、跨关键词/target/读者复用游标、权限变化；未授权读取仍被拒绝，筛选在分页前生效。
- 覆盖新增、改名、元数据更新、删除、旧库升级、重复迁移、回填失败后重试及维护重建。直接执行旧数据写入和实际迁移，不只 mock 出“已完成”。
- 注入可识别的索引维护缺项，证明独立 oracle 能发现静默漏查；索引查询返回零条本身不构成健康证明。
- 回归 OPDS/Mihon 匹配、分页和真实总数，以及资料库既有排序与读者筛选。并发变更测试只断言已承诺的单批一致、错误语义及前端去重，不假定快照。

### 前端行为

- 以既有搜索弹窗交互测试为基础，补充真实搜索会话 hook 驱动的组合测试；使用可控响应而不是仅 mock 静态 hits。
- 覆盖快速输入、旧响应晚到且取消无效、切换 target、关闭、重开、重置、读者或连接上下文变化，验证旧结果不能回写或被回车打开。
- 区分初始提示、等待、首批失败、成功无结果、成功有结果；重试保留查询且可恢复。
- 覆盖继续加载、连按、追加失败重试、响应重叠去重、末页、游标失效后的显式重新搜索；验证数量与 has_more 展示。
- 验证键盘与鼠标选择不越界，追加不破坏有效选择，类型导航仍正确，分数不再展示，本地化及状态可访问性正常。

### Prior art 与验证门禁

- 复用既有 gram 搜索、存量回填、双路径系列搜索、迁移幂等性及分页总序测试的夹具和表驱动风格；复用真实 HTTP 搜索和协议路由测试的装配方式。
- 前端沿用 Vitest、既有弹窗交互断言与可控请求测试习惯，不引入第二套测试框架或 transport adapter。
- 后端完成包级及全量测试、格式检查与 lint；前端完成测试、构建及 lint；按实际改动运行 SQL 绑定和前端契约再生成及漂移检查。规格本身不代表这些实现门禁已经通过。

### 性能验收

- 在同一机器与 SQLite 设置下，以冻结的合成藏书记录基线和新实现；规模至少覆盖 20 万本书、2 万个系列，分别包含短词、长词、稀疏与广泛命中。
- 预热后每场景至少测量 100 次并报告 p50/p95，记录硬件、数据分布、页大小及缓存条件，不以某次单样本耗时证明性能。
- 对新旧命中语义一致的普通名称查询，新实现首批 p95 不超过旧实现的两倍；对新增宽松匹配场景记录独立结果，不拿不同命中数量的查询直接比较。
- 新实现深页游标请求 p95 不超过相应首批的两倍；覆盖靠近末尾的可用页，证明没有前端累计拉取所有前页或隐蔽 offset 放大。
- 升级额外搜索派生数据回填与同规模完整维护重建比较，耗时不超过后者两倍；区分必要回填与其他既有迁移开销。检查索引驱动的候选访问，禁止以每次全藏书归一化来通过功能测试。
- 这些是本规格的待执行相对预算，不是已测量结论；计时不作为普通单元测试的脆弱墙钟断言。若预算失败，应优化或显式调整规格，不得省略性能验收后声称完成。

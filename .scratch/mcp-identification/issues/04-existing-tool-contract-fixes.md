# 04: 现有 MCP 工具契约整改

**What to build:** 修掉首版试用中让 agent 迷路的几处契约问题，现有 agent 马上就能受益。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] `library_find_series` 的 `missing_fields` 改为：所列字段中任一缺失即命中。工具描述同步说明。
- [x] 每个工具的结果都带 JSON 文本副本。回归测试逐一覆盖所有已注册的工具；以后新增的工具缺少文本副本时，测试失败。
- [x] 统一拒绝时附一句下一步提示（例如「ID 应取自本次查询或领取的结果」），但仍不区分「对象不存在」和「无权访问」。
- [x] 本 effort 保留下来的工具，描述压到约 400 字符以内，并各附一个调用示例。将由 19 下线的工具不必改写。
- [x] 工具清单仍按凭据当前的能力过滤，行为不变。
- [x] MCP 接入文档中受影响的描述同步更新；后端门禁通过。

## Comments

本票按规格「留给实施决定的工程细节」（工具命名与参数形状一项）自己定下的取值：

- **描述上限**：按 400 个字符（rune）硬性检查，不留「约」的余量，这样上限才有一条可执行的判据。示例统一写成描述末尾的 `Example: {JSON}`，示例里的参数必须在输入 schema 中声明，弱模型照抄就是一次合法调用。将由 19 下线的 9 个工具列在测试的 `legacyIdentificationTools` 里豁免，19 删工具时一并删掉。
- **拒绝提示**：全部工具共用同一句 `errMCPDenied`（「ID 只取自本凭据自己的结果，如 library_find_series / library_list_books；已是如此则说明授权不再覆盖，应上报而非重试」），不按工具定制。这样不管拒绝出于什么原因，文本都不会因原因不同而分化。
- **图片工具的文本块**：原来的说明句换成结构化结果的 JSON（图片字节本来就不进 JSON），后面跟图片块，顺序与 `images` 一致。
- **文本副本回归**：`TestMCPEveryToolResultCarriesItsJSONText` 对全能力凭据的工具清单逐一要求「成功调用且某个文本块的 JSON 等于 structuredContent」。清单里某个工具没在这里被成功调用，测试就失败。所以以后新增工具（包括并行票）合入时，必须在这个测试里补一次成功调用，描述也必须满足上面的长度和示例检查。

# 03: 识别结论与识别状态

**What to build:** 系统按「系列 × 来源」持久保存系列识别，并由此推导每个系列的识别状态。升级时从历史推导初始状态：已应用的提案成为人工确认的识别，被驳回提案的条目成为排除候选。所有者在系列详情页能看到识别结论，可以把系列设为已审定，也可以撤回；agent 能通过 MCP 查询各识别状态下的系列数。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 识别结论包含：来源条目、确认者类别（人，或 agent 及其凭据归属）、确认时间、一句理由、来源条目的原名与别名。一个系列可以有多个来源的识别结论。
- [ ] 识别状态由识别结论、上报和人的决定推导而来，不是可单独编辑的字段。取值为：未处理、已识别、待人工、待复核、查无此作、已审定。本票实际产生的状态至少包括未处理、已识别、已审定；其余状态的存储与推导规则要就位，供后续票使用。
- [ ] 升级推导：
  - 已应用的提案转为对应来源的人工确认识别，条目取自提案的来源标识；
  - 被驳回提案的条目记为该系列的排除候选；
  - 待审提案不动；
  - 重复执行结果不变。
- [ ] 资料库路径迁移后，识别结论保留；系列删除时，它的识别结论一并删除。
- [ ] 管理员网页接口与系列详情页只读展示识别状态和各来源的识别结论（条目链接、确认者、确认时间），并提供设为已审定、撤回已审定两个操作。
- [ ] MCP 进度查询工具（`read`）返回各识别状态下的系列数，受凭据的资料库限制。工具描述在约 400 字符以内并附一个调用示例，结果带 JSON 文本副本。
- [ ] 新的响应结构纳入生成契约，无漂移；改了 SQL 的，重新生成的绑定无漂移。
- [ ] 生产组装集成测试（`bootstrap.Open` + 通用 MCP 客户端 + 管理员 HTTP）覆盖历史推导、已审定的设置与撤回、进度计数。前端组件测试覆盖详情页的识别区。
- [ ] 后端门禁与前端 test/build/lint 通过。

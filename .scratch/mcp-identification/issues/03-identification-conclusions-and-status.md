# 03: 识别结论与识别状态

**What to build:** 系统按「系列 × 来源」持久保存系列识别，并由此推导每个系列的识别状态。升级时从历史推导初始状态：已应用的提案成为人工确认的识别，被驳回提案的条目成为排除候选。所有者在系列详情页能看到识别结论，可以把系列设为已审定，也可以撤回；agent 能通过 MCP 查询各识别状态下的系列数。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 识别结论包含：来源条目、确认者类别（人，或 agent 及其凭据归属）、确认时间、一句理由、来源条目的原名与别名。一个系列可以有多个来源的识别结论。
- [x] 识别状态由识别结论、上报和人的决定推导而来，不是可单独编辑的字段。取值为：未处理、已识别、待人工、待复核、查无此作、已审定。本票实际产生的状态至少包括未处理、已识别、已审定；其余状态的存储与推导规则要就位，供后续票使用。
- [x] 升级推导：
  - 已应用的提案转为对应来源的人工确认识别，条目取自提案的来源标识；
  - 被驳回提案的条目记为该系列的排除候选；
  - 待审提案不动；
  - 重复执行结果不变。
- [x] 资料库路径迁移后，识别结论保留；系列删除时，它的识别结论一并删除。
- [x] 管理员网页接口与系列详情页只读展示识别状态和各来源的识别结论（条目链接、确认者、确认时间），并提供设为已审定、撤回已审定两个操作。
- [x] MCP 进度查询工具（`read`）返回各识别状态下的系列数，受凭据的资料库限制。工具描述在约 400 字符以内并附一个调用示例，结果带 JSON 文本副本。
- [x] 新的响应结构纳入生成契约，无漂移；改了 SQL 的，重新生成的绑定无漂移。
- [x] 生产组装集成测试（`bootstrap.Open` + 通用 MCP 客户端 + 管理员 HTTP）覆盖历史推导、已审定的设置与撤回、进度计数。前端组件测试覆盖详情页的识别区。
- [ ] 后端门禁与前端 test/build/lint 通过。

## Comments

本票按规格「留给实施决定的工程细节」自己定下的取值：

- **持久化结构**：`internal/database/schema_identification.sql` 建识别结论、排除候选、上报、查无此作、已审定五张表和一张推导完成标记表，全部按 `series_id` 外键级联删除；路径迁移不换系列 ID，所以结论原样保留。时间一律存 Unix 毫秒，方便 06 用注入的时钟比较租约。证据包和租约的表留给 05、06。
- **状态推导**：视图 `series_identification_status` 是识别状态的唯一定义，每次启动重建，规则改了存量库也会跟上。优先级从高到低：已审定 > 待复核 > 待人工 > 已识别 > 查无此作 > 未处理。上报的 `class` 决定它对状态的影响：`identification` 对应待人工，`recheck` 对应待复核，`note` 不影响状态。`category` 的取值留给 06、11、14 定义。查无此作用 JSON 数组记录 `searched_sources`，供 15 比对新启用的来源。
- **存量推导**：在 `bootstrap.Open` 里执行一次，推导和完成标记在同一个事务里提交，中断后重跑结果相同。推导规则：
  - 只认 `status` 为 `applied` 和 `rejected` 的提案。部分应用仍待审的提案，以及 `supplemented_closed` 的提案都不转换。
  - 来源按提案行的 `provider` 归一化，为空时改用 raw_payload 里的 Provider。条目编号取 `source_id`，缺失时从来源 URL 的形状解析（MangaDex 取 UUID）。
  - 没有来源条目的提案跳过，包括 LLM 提案和 `delegated` 多来源提案。
  - 同一系列、同一来源有多次应用时，取最近一次。
  - 同一条目既被应用过又被驳回过时，只记识别，不记排除候选。
- **条目命名**：`identification.SourceKey` 和 `identification.EntryOf` 是来源键和条目编号的唯一入口，05、06 复用它们，保证不同写入方对同一条目的命名一致。条目 URL 只保留 http(s) 的，否则按来源的固定形式重新拼出。
- **管理员接口**：`GET /api/identification/series/{id}`，以及 `PUT` 和 `DELETE /api/identification/series/{id}/owner-review`。整个 `/api/identification/` 前缀只对管理员开放，读取也一样，因为结论里带着凭据和账户归属。响应都是操作后的权威状态。重复设为已审定会保留第一次的决定；撤回一个本来就没有审定的系列不做任何改动。
- **MCP 工具**：`library_identification_progress`，能力为 `read`。参数 `library_ids` 可选，默认取凭据的全部资料库；其中任何一个没有授权，整次调用都拒绝，不缩小范围。结果形如 `{library_ids, series, statuses}`，六个状态的计数总是齐全。授权范围复用新增的 `delegated.Service.Libraries`。
- **前端**：识别区放在系列详情侧栏新增的「识别」页签里，只对管理员显示。
- **时钟**：`identification.Service` 内部的当前时间默认取 `time.Now`。`bootstrap.Options` 的时钟注入接缝留给 06 加。

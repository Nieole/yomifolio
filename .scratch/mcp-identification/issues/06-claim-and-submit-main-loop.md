# 06: 主循环：领取与提交裁决

**What to build:** agent 一次领取一批带证据包的系列，对每个系列提交裁决：「识别为某来源的某候选」「查无此作」或「上报」，系统据此记录识别结论、更新识别状态。多个 agent 可以并行领取，互不冲突。

**Blocked by:** 03 识别结论与识别状态；05 证据包预取（手动回填）

**Status:** ready-for-agent

- [ ] 领取（`metadata_write`）：
  - 可按资料库过滤，每批最多 20 个；
  - 只发放证据包已就绪的未处理系列，已审定的系列不发放；
  - 返回证据包和租约，整个响应在约 30 KB 量级。
- [ ] 并行领取不重叠；租约到期后，未提交的系列退回未处理。`bootstrap.Options` 增加一个只供识别模块使用的时钟，生产环境用真实时间。
- [ ] 没有可领取的系列时，响应说明原因：是全部处理完毕，还是预取尚未就绪。
- [ ] 提交（`metadata_write`）：每个系列一条，附一句理由。
  - 识别：一次可以识别到多个来源。
  - 查无此作：记录判定时搜过的来源。
  - 上报：必须带分类。识别类（多候选难分、版本不确定、来源无结果但疑似存在）使系列进入待人工；非识别类（疑似目录分组错误、疑似重复、标签问题）只作为备注，不改变识别状态。
- [ ] 以下情况，该系列被拒绝并说明原因：引用了排除候选；引用了不属于该系列证据包的候选；租约已失效且系列已被他人领取。
- [ ] 结果逐个系列返回，不保证整批原子；同一请求键重放时返回原结果；写入前重新检查当前授权。
- [ ] 本票的识别结论只记录身份，不补充元数据，补充由 07 接上。
- [ ] 新工具的描述在约 400 字符以内并附调用示例，结果带 JSON 文本副本，并按能力出现在工具清单中。
- [ ] 集成测试推进注入的时钟来验证租约到期，并覆盖并行领取、部分成功、重放和各类上报。
- [ ] 后端门禁通过，生成契约无漂移。

# 06: 主循环：领取与提交裁决

**What to build:** agent 一次领取一批带证据包的系列，对每个系列提交裁决：「识别为某来源的某候选」「查无此作」或「上报」，系统据此记录识别结论、更新识别状态。多个 agent 可以并行领取，互不冲突。

**Blocked by:** 03 识别结论与识别状态；05 证据包预取（手动回填）

**Status:** ready-for-agent

- [x] 领取（`metadata_write`）：
  - 可按资料库过滤，每批最多 20 个；
  - 只发放证据包已就绪的未处理系列，已审定的系列不发放；
  - 返回证据包和租约，整个响应在约 30 KB 量级。
- [x] 并行领取不重叠；租约到期后，未提交的系列退回未处理。`bootstrap.Options` 增加一个只供识别模块使用的时钟，生产环境用真实时间。
- [x] 没有可领取的系列时，响应说明原因：是全部处理完毕，还是预取尚未就绪。
- [x] 提交（`metadata_write`）：每个系列一条，附一句理由。
  - 识别：一次可以识别到多个来源。
  - 查无此作：记录判定时搜过的来源。
  - 上报：必须带分类。识别类（多候选难分、版本不确定、来源无结果但疑似存在）使系列进入待人工；非识别类（疑似目录分组错误、疑似重复、标签问题）只作为备注，不改变识别状态。
- [x] 以下情况，该系列被拒绝并说明原因：引用了排除候选；引用了不属于该系列证据包的候选；租约已失效且系列已被他人领取。
- [x] 结果逐个系列返回，不保证整批原子；同一请求键重放时返回原结果；写入前重新检查当前授权。
- [x] 本票的识别结论只记录身份，不补充元数据，补充由 07 接上。
- [x] 新工具的描述在约 400 字符以内并附调用示例，结果带 JSON 文本副本，并按能力出现在工具清单中。
- [x] 集成测试推进注入的时钟来验证租约到期，并覆盖并行领取、部分成功、重放和各类上报。
- [x] 后端门禁通过，生成契约无漂移。

## Comments

本票按规格「留给实施决定的工程细节」自己定下的取值（都不碰已确认的产品或安全边界）：

- **工具命名与参数**：领取 `library_claim_series {library_ids?, limit?}`（limit 1–20，默认 20；越界拒绝），提交 `library_submit_verdicts {request_key, lease_id, verdicts:[{series_id, verdict, candidate_ids?, category?, reason}]}`，两者都挂 `metadata_write`。`verdict` 取 `identify`/`not_found`/`escalate`，输入 schema 给出枚举。领取结果带 `next` 一句下一步提示；提交结果逐系列给 `accepted`、`status`（识别状态），被拒的给 `problem` 代码和 `message` 下一步。
- **租约**：时长 30 分钟，一次领取一个 `lease_id`。一个弱模型处理 20 个系列通常用不了这么久，崩溃会话的系列半小时内退回。租约过期但没被别人领走时，原租约照样能提交；被新领取接手后，原租约的提交以 `claimed_by_other` 拒绝。提交必须带领取时的 `lease_id`，没被领取过的系列以 `not_claimed` 拒绝。领取在同一个写事务里重查每个资料库的当前授权并写租约，SQLite 的 immediate 事务把并发领取串行化，所以不会重叠。
- **批次字节预算**：整批 JSON 不超过 30 KiB，逐个系列往里放，下一个放不下就截止，没放进去的系列不领取，下次领取再发。单包保持 05 的 4 KiB 原样，不为凑满 20 个再压缩证据。理由：4 KiB × 20 必然超出 30 KB 量级，二者只能取一个当硬约束；弱模型的上下文才是约束的来源，证据完整度比批次大小更重要。按 05 的上限，一批至少能放 7 个满额证据包；实测满额包一批 8 个，约 29.9 KB。
- **空批原因**：`prefetch_pending`（有未处理系列还没证据包，优先报这个）、`all_claimed`（就绪的系列都在有效租约下，包括调用者自己的）、`all_processed`（没有未处理系列）。比票面多一个 `all_claimed`，否则别的会话正在处理时只能谎报成另外两种。
- **上报分类**：识别类 `ambiguous_candidates`、`uncertain_edition`、`missing_from_sources`；非识别类 `directory_grouping`、`suspected_duplicate`、`tag_problem`（供 17 复用）。系统分类 `new_book_contradiction` 和 11 的复核分类不经本工具提交。备注不结束租约，同一租约之后还能对该系列给出识别、查无此作或识别类上报；同一系列已有同分类的未关闭备注就不再重复记一条。备注不改变状态，租约过期后系列会再被领取，领取结果用 `open_notes` 列出已有备注的分类，提醒 agent 这次要给结论。
- **校验与拒绝**：识别引用 1–5 个候选、每个来源至多一个；查无此作不带候选和分类；理由去掉首尾空白后 1–1000 字节。拒绝顺序：格式 → 授权（不存在与无权读来相同）→ 请求键 → 状态已不是未处理 → 租约 → 候选（排除候选先于不在证据包）。被拒的系列原样不动。
- **查无此作的来源**：记证据包里状态为 `available` 的来源，当时不可用的来源不算搜过。
- **重放**：请求键按「凭据 × 请求键 × 系列」保存该系列的判定结果，与判定写在同一事务里。同键同内容重放直接返回原结果，先重查当前授权；同键换了内容以 `request_key_reused` 拒绝。格式错误、授权拒绝和写入失败不保存，重试时重新判定。
- **持久化**：`identification_leases`（每系列一行，结束判定时删除，过期行等下次领取覆盖）和 `identification_verdicts`（判定结果），都随系列级联删除。
- **所有者视图**：`GET /api/identification/series/{id}` 增加可选的 `not_found`（搜过的来源、确认者、时间、理由）和 `escalations`（未关闭的上报），用来核对查无此作和上报确实落库，也供 12、13 使用。
- **时钟**：`bootstrap.Options.Clock` 同时交给识别服务和预取，证据包的抓取时间与租约用同一时钟，留给 15 推进时钟验证过期刷新。

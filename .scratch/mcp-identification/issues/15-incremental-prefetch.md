# 15: 增量预取

**What to build:** 增量整理不再需要所有者手动操作：
- 扫描出新系列后，自动为它们准备好证据包；
- 证据包太旧时，在被领取时刷新；
- 新启用一个来源后，查无此作的系列对这个来源重新开放。

**Blocked by:** 05 证据包预取（手动回填）；06 主循环：领取与提交裁决

**Status:** ready-for-agent

- [x] 扫描收尾时串联一次低优先级预取，只处理新出现的未处理系列。以下两点按词汇表的判据确定，并写入规格：
  - 它和手动回填的关系，是另一个变体还是对同一任务的合并发起；
  - 这个任务是否可续跑。
- [x] 被领取的证据包抓取时间超过 30 天的，安排后台刷新。刷新期间这个系列是暂不发放，还是带旧证据包发放，规则要写明。
- [x] 通过配置新启用一个来源后，查无此作的系列只针对这个新来源重新变为可处理；已识别的系列不重新处理。
- [x] 不把系列推给 agent，agent 仍然按识别状态自己拉取。
- [x] 集成测试覆盖：真实扫描触发串联预取；推进时钟验证刷新；启用来源后的重新开放。
- [ ] 后端门禁通过。

## Comments

**用户决定（2026-11-25）**：agent 经 MCP 发起的委托扫描（`ScanLibraryWithPolicy` 路径，现状不串联任何后续任务）收尾时，也串联这次低优先级预取，只处理该次扫描涉及资料库里新出现的未处理系列。

本票按规格「留给实施决定的工程细节」自己定下的取值（变体、可续跑和刷新规则已写入规格「任务与运行」「证据包与预取」两节）：

- **预取变体与可续跑**：新增变体 `incremental`（资料库作用域），与手动回填的 `all_libraries`/`one_library` 是不同身份，可以同时跑；可重试，也**可续跑**。手动回填仍不可续跑。判据与理由见规格。扫描收尾、领取发起的增量运行发起方都记为「串联」。
- **「新出现的系列」怎么认**：扫描器每个已提交批次把它新建的系列（扫描开始时不存在的）经新钩子 `Scanner.SetCreatedSeriesHook` 交出，bootstrap 把它们记成持久的预取请求（`identification_prefetch_requests` 表）。扫描收尾经 `scanning.Effects.Prefetch` 发起该库的增量运行；运行开始时才读请求，所以排队合并、重启续跑都不丢。没有来源应答的系列请求保留，下次扫描或领取时再试；不再需要证据包的请求由下一次增量运行清掉。扫描被取消时不串联，部分归档失败时照常串联（否则库里有一个坏文件，新系列就永远等不到证据包）。
- **「低优先级」**：引擎没有优先级，这里指扫描结束后才发起、不影响扫描结果；与其它预取和重搜共用同一份各来源节拍，不提高任何来源的请求速率；ComicInfo 走后台磁盘作业。没有另加批间停顿：每个来源的节拍已经是秒级。
- **证据包是否「有效」**：抓取不超过 30 天（`identification.PacketMaxAge`），并且如果系列被新来源重开，抓取时间晚于该来源启用的时间。领取只发放有效证据包的系列；无效的按领取顺序、每次最多 `limit` 个记为请求并在提交后发起刷新，刷新期间暂不发放。`library_identification_progress` 的 `prefetch.ready` 也改为只数有效证据包，与领取口径一致。
- **刷新保留重搜**：刷新重新搜派生词和证据包里记下的自定义重搜词（票 09 的 `searches`），用新的抓取时间整包重建；刷新期间如果证据包被重搜或别的运行改过，这次不覆盖，请求保留待下次。
- **「新启用的来源」**：`identification_enabled_sources` 表记每个已启用来源从什么时候启用，在 `bootstrap.Open` 和每次配置保存或重载后同步（第一次同步时已启用的来源记为 0，即一直启用）；停用就删掉，再启用算新启用。查无此作的判定时间早于某来源启用时间、且没搜过它，就重开：状态视图把它算作未处理，增量刷新只问重开的来源。判定时已启用但不可用的来源不算新启用，不会重开。再判查无此作时搜过的来源取并集；识别成功就删掉旧的查无此作。
- **来源收窄**：`metadata.SourceFanout` 新增 `Only` 字段，非空时只问其中列出的已启用来源。

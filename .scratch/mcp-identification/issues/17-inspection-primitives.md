## Comments

本票按规格「留给实施决定的工程细节」（工具命名与参数形状、持久化结构）自己定下的取值：

- **工具命名与参数**：查重 `library_find_duplicate_series {library_ids?, offset?, limit?}`，标签统计 `library_count_tags {library_ids?, sort?, offset?, limit?}`，上报 `library_report_series {series_id, category, reason}`，三者都挂 `read`。`library_ids` 的规则与进度工具相同：默认取凭据的全部资料库，任何一个没有授权，整次调用都拒绝。翻页用 `offset`/`next_offset`，`next_offset` 只在还有下一页时出现。查重和统计的结果是全量重算后排序再切页，所以偏移翻页就够用，不需要游标。
- **查重**：分两类组，`same_entry`（识别结论指向同一来源条目，键写成 `source:entry_id`，与证据包候选 ID 同形）排在前，`same_name`（目录名或标题规范化后相同，键是规范化后的名称）排在后，同类内按键排序。规范化沿用资料库搜索的规范化，直接读它维护的 `series_search_text` 投影，不重复计算。目录名和标题都参与比对：标题被识别补充替换后，同名目录仍然能凑成一组。一个系列可以出现在多个组里。只统计授权范围内的系列，所以一组至少要有两个范围内的系列。每组按 ID 列出前 10 个系列，给出总数 `series_count`。每个系列带目录名、标题、书数和识别状态，不带备注和结论的归属，因为普通用户的凭据也能用这个工具。每页默认 10 组、最多 20 组。
- **标签统计**：每个标签给出范围内带它的系列数，再附按 ID 取的前 3 个 `sample_series_ids`，方便 agent 挑一个系列上报 `tag_problem`。`sort` 取 `count`（默认，按使用数从高到低，再按名称）或 `name`（按规范化名称排，写法不同的同义标签会排在一起）。`total` 是范围内用到的不同标签数。每页默认 50 个、最多 100 个。
- **字节预算**：查重和统计的单页 JSON 不超过 30 KiB，与领取批次同一个量级。放不下下一项时这一页就截止，`next_offset` 指向第一项没放进来的。每页至少放一项。
- **上报**：只接受三个备注分类 `directory_grouping`、`suspected_duplicate`、`tag_problem`。识别类分类、系统分类和未知分类都按参数无效拒绝，提示要识别类上报得走 `library_submit_verdicts`，那需要 `metadata_write`。理由的规则与提交裁决相同：去掉首尾空白后 1–1000 字节。写入复用 06 的上报存储和同一条去重规则（`raiseOnce`，`Submit` 的备注也改为走它）：同一系列已有同分类的备注时不再新记一条，不论它还开着还是已被所有者关闭（见下方用户决定），结果给出 `recorded:false`，原备注的理由保持不变。识别类上报不受「关闭即挡住」约束，只在同分类仍未关闭时不重复记。所以重复调用是幂等的，不需要请求键。授权在记录事务内用 `read` 重查，系列不存在和没有授权读来相同。备注不需要领取，也不结束任何租约。任何识别状态的系列都可以挂备注，包括已审定的：已审定只挡领取和识别补充，备注两样都不碰。结果带系列当前的识别状态，用来表明备注没有改变它。
- **工具注解**：查重和统计标为只读。上报会写一条备注，所以不标只读，标为幂等、非破坏性。

**用户决定（2026-11-25）**：所有者关闭的备注挡住同系列同分类的再次上报。经 `library_report_series` 再报返回 `recorded:false`；经 `library_submit_verdicts` 再报，这条裁决照常接受，但不新记备注。两条路径都不改变识别状态。换一个分类，或者换一个系列，照常记录。测试 `TestNoteTheOwnerClosedIsNotRaisedAgain` 目前还没有公开的关闭入口（由票 12 提供），所以经存储层把备注置为关闭来构造前置状态（辅助函数 `closeNotes`）。12 接上之后，改走它的公开入口。

# 10: 作者校正与封面改善成为独立原语

**What to build:** 把 agent 需要自己判断的两类改动从逐系列补充命令中拆出来，成为独立操作，规则不变：一类是系列内作者校正，另一类是用本系列的归档页改善自动封面。这一步为 19 下线旧补充命令做准备。

**Blocked by:** 02 元数据补充与证据来源解耦；06 主循环：领取与提交裁决

**Status:** done

- [x] 作者校正：
  - 只调整目标系列的作者关联，不改共享作者记录；
  - 被替换的作者必须属于当前作者，替换后的作者必须有该系列已识别来源的证据支持；
  - 按整组校验期望值，写原因、留收据，可以撤销。
- [x] 封面改善：
  - 只接受授权范围内同一系列的归档书和页码，并附一段比较说明；
  - 只改未锁定的归档自动封面，人工封面受保护；
  - 文字和封面在同一操作中一起生效的保证不变。
- [x] 两个原语（`metadata_write`）的结果和收据都与现有补充一致，可以用现有工具查询、撤销、清理。
- [x] 新工具的描述在约 400 字符以内并附调用示例，结果带 JSON 文本副本。
- [x] 现有作者校正和封面相关的集成测试迁移到新原语上，用等价断言后仍然通过。
- [x] 后端门禁通过。

## Comments

**用户决定（2026-11-25）**：作者校正要有一个读取入口，新增只读原语，不扩展既有工具，也不放宽整组期望值。落成 `library_get_series_authors {series_id}`（`read`），返回 `authors`（当前作者组，原样可当 `expected_authors`）和 `sources`（每个已识别来源的 `source`、`entry_id` 与快照里的署名 name+role）。证据规则与 `library_correct_authors` 同一份（`identification.SourceEvidence`，经同一个注入函数读取），没有任何已识别来源时 `sources` 为空。只要 `read` 就能读；越出凭据授权的系列与不存在的系列读来同一句拒绝。作者校正的描述指向它。

本票按规格「留给实施决定的工程细节」（工具命名与参数形状）自己定下的取值：

- **工具**：`library_correct_authors {request_key, series_id, expected_authors, corrections:[{from, to, reason}]}` 与 `library_improve_cover {request_key, series_id, book_id, page, reason}`，都挂 `metadata_write`。封面还要当前的 `read`：选页要读归档内容，与旧路径的准入一致。两者的结果都是普通的 `enrich` 收据，现有的查询、撤销、清理工具直接可用；请求键与其它补充共用一个重放空间，命令摘要各带一个判别字段，同一键换了命令即拒绝。
- **「已识别来源的证据」**：取该系列每条识别结论背后的来源快照——证据包里按候选 id 存的快照；存量推导出的结论没有证据包，就用它来自的已应用提案的原始结果。证据在写事务里重读，准入之后识别变了就记一条冲突收据。没有任何已识别来源快照的系列，所有校正都被拒绝。
- **作者校正只做校正**：结果是「当前作者组 − 每个 from + 每个 to」，不再把来源的全部作者一并追加。追加来源作者是 07 识别补充的策略，原语只承担需要判断的替换。整组期望值、from/to 的规则、原因上限、50 条上限都沿用旧规则。
- **封面期望值由服务端取**：准入时读到的当前封面就是期望值，写事务里当前封面不再是它、或不再是未锁定的归档自动封面，就记冲突。调用方不再传封面快照（19 之后也没有工具能读到封面路径），`quality_compared` 这个确认位也不再收，`reason` 就是比较说明，收据里的 `cover_selection.quality_compared` 仍记为 true。
- **「文字和封面一起生效」的落法**：两个原语彼此独立，封面原语不带文本字段，所以这一条落在封面切换、比较说明所在的收据和撤销材料引用同一事务提交上：任一步失败封面都不变：切换失败留一条 `failed` 收据，引用登记或提交失败整笔回滚、不留收据。测试用触发器分别打断这三步。
- **受保护的封面记冲突收据**：人工封面、锁定的封面、所有者选过页的封面，返回 `conflict` 收据而不是拒绝，agent 从收据就能看出它受保护；格式错误、别的系列的书、越界页码照旧直接拒绝，不留收据。
- **不写字段来源记录**：与普通补充一致。作者校正与封面都不是来源字段，11 的「改正字段」也就碰不到它们。
- **测试**：新原语的等价断言在 `mcp_author_correction_test.go`、`mcp_cover_improvement_test.go`。旧工具的作者与封面测试原样保留，守着 19 下线前仍在的旧命令，由 19 随工具一起删。旧测试里借提案读取钩子做的「准入后、写入前」竞态用例没有移植：新原语没有这个钩子，事务内的锁、成员和授权围栏与旧路径是同一段代码。

# 09: 重搜单个系列

**What to build:** 遇到难判的系列，agent 或所有者可以用自定义搜索词再搜一次，结果并入该系列的证据包。

**Blocked by:** 05 证据包预取（手动回填）

**Status:** ready-for-agent

- [x] MCP 原语（`metadata_write`）和管理员网页接口共用同一个用例。
- [x] 复用 01 的扇出和来源限速。
- [x] 结果按证据包规则并入：每个来源的候选数有上限、附比对信号、剔除排除候选；原有候选不丢弃；记录本次的搜索词和时间。
- [x] 搜索词的长度和内容有限制。
- [x] 耗时的搜索作为一次运行，可以查询和取消；断线不会取消它。
- [x] 新工具的描述在约 400 字符以内并附调用示例，结果带 JSON 文本副本。
- [x] 集成测试覆盖：并入、去重、剔除排除候选、来源失败。
- [x] 后端门禁通过，生成契约无漂移。

## Comments

本票按规格「留给实施决定的工程细节」自己定下的取值（都不碰已确认的产品或安全边界）：

- **工具命名与参数形状**：MCP 工具 `library_research_series`（`metadata_write`），参数 `{series_id, query, wait_ms?}`；管理员接口 `POST /api/identification/series/{id}/research`，请求体 `{query, wait_ms?}`。两者都调 `identification.Service` 的同一个用例，结果都是 `ResearchResult{series_id, query, status, run_id, added, dropped, packet}`。
  - `status` 取 `completed`、`already_searched`、`running`、`failed`、`cancelled` 之一。
  - 用例最多等 `wait_ms` 毫秒（默认 20000，上限 30000，和 `library_wait_run` 一致），等到就返回并入后的证据包。等不到时返回 `running` 和 `run_id`，运行在后台继续：agent 用 `library_wait_run` 等它跑完，再用同样的参数调用一次，读到这次运行存下的结果，不会再搜一遍。
  - 理由：弱模型在常见情况下一次调用就能拿到新候选的 id，不必再加一个读证据包的工具。
- **搜索词限制**：
  - 必须是合法 UTF-8，不能含控制字符或格式字符（Unicode Cf，例如双向覆盖符、零宽字符）。
  - 连续空白合并成一个空格后，长度为 1–100 个字符，与预取派生词的上限相同。
  - 规范化后必须至少含一个字母或数字。
  - 搜索词原样发给来源，不做目录名那套清洗。
- **重复的词不再搜**：一个词规范化后，如果等于包里某个派生词，或等于已记录的某次搜索，就直接返回当前的包（`already_searched`），不建运行。这次重复调用的 `added` 沿用那次搜索记下的 id。
- **合并规则**：
  - 自定义词向每个来源取前 5 条。去掉包里已有的、被排除的和重复的条目后，按「标题与本地名称一致的在前」排序，每个来源最多新增 3 条，比对信号对照包里原有的本地线索计算。
  - 原有候选原样保留、位置不变；新候选排在同一来源原有候选的后面。
  - 来源只要应答过一次就算可用，所以之前不可用、这次应答了的来源会转为可用。
  - 每次搜索在包的 `searches` 里记一条：`{query, searched_at, added, dropped}`。包只保留最近 5 条搜索记录。
  - `fetched_at` 仍表示预取时间，重搜不改它。
- **字节预算**：重搜过的包上限为 8 KiB（预取包是 4 KiB）。超出时依次：去掉本次新增候选的摘要（从后往前），再从排名最低的本次新增候选删起，最后删最旧的搜索记录。原有候选从不删，删掉的新候选数记在 `dropped` 里。06 的整批领取按字节截断，30 KiB 至少放得下三个重搜过的包。
- **没有证据包的系列**（例如已识别的系列，预取不会处理它）：先像预取那样读本地线索与 ComicInfo，用派生词搜一遍并建好包，再并入自定义词的结果，这样包始终覆盖派生词。预取保存时如果发现包已经由重搜写下，就保留那份包，不覆盖。
- **来源失败**：只要有一个来源应答了自定义词，就照常并入。没有任何来源应答时，运行记为失败，包保持原样，这个词也不记录，之后可以用同一个词重试。
- **运行与身份**：
  - 任务类型 `evidence_research`，作用域是系列所在的资料库，变体为 `series:<系列 id>`。agent 发起的运行经 `PrepareRun` 带上凭据，所以 `library_get_run`、`library_wait_run`、`library_cancel_run`、`library_list_runs` 都能用。
  - 每个发起方（所有者，或每个凭据）对每个系列只有一个任务。同一发起方的重搜还在排队时再发起一次，会并进那条排队的运行，结果返回 `running` 和那条运行的 id。
  - 可以取消，不能暂停，没有重启函数，所以不可重试：要重搜就再发起一次。
  - 断线只结束等待，运行照常跑完。
  - 每访问一个来源前后都调用运行检查点，agent 的检查点包含授权复查。写入事务里会再查一次授权：agent 用 `AuthorizeTx`，所有者重查管理员身份。
- **已审定**：agent 不能重搜已审定的系列，会收到「owner-reviewed」提示；写入前也会再查一次状态。所有者可以重搜任何状态的系列。理由：已审定的系列 agent 不会领取，重搜对它没有用处，这与「已审定的系列不交给识别流程」一致。
- **限速**：复用预取的 `SourcePacer` 与 `identification.source_intervals_ms` 配置，重搜和所有预取运行共享同一份节拍。

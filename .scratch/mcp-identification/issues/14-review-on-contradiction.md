# 14: 待复核检测

**What to build:** 已识别的系列加入新书时，如果新书的本地线索与识别结论矛盾，系列转为待复核，等人确认；不矛盾就什么都不做。

**Blocked by:** 03 识别结论与识别状态

**Status:** done

- [x] 扫描新增书之后，检查 ComicInfo 系列名等本地线索是否与该系列的识别结论矛盾，比对时把原名和别名也算进去。矛盾的判据在本票确定，并写入规格。
- [x] 判定为矛盾时，系列转为待复核，原识别带来的字段不变；不矛盾或者没有线索时，状态不变。
- [x] 检查过程不访问外部来源，不阻塞扫描主流程；检查出错不会导致扫描失败。
- [x] 待复核的系列出现在进度计数和系列详情页里。
- [x] 集成测试用真实扫描，分别加入 ComicInfo 矛盾和不矛盾的书。
- [x] 后端门禁通过。

## Comments

**用户决定（2026-11-25）**：扫描侧保护带来源记录的值，本票实现。现状是已有系列加入带 ComicInfo 的新书或强制重扫时，`PrepareScanUpdate` 用 ComicInfo 覆盖或清空未锁的标量，连载状态没锁就总被清空。改为：字段当前值有来源记录、且与记录值一致（识别补充或历史提案应用写入的）时，扫描不覆盖也不清空；没有来源记录的字段照旧由 ComicInfo 覆盖。不为此加锁，保证 agent 的「改正字段」仍然可用。

本票按规格「留给实施决定的工程细节」自己定下的取值：

- **矛盾判据**：线索只取扫描**新加入**、扫描开始前已存在的系列的书的 ComicInfo 系列名；改名重连、强制重扫重读的旧书不算。只检查有识别结论、未审定、没有未处理复核上报的系列。系列名与该系列所有来源结论的标题、原名、别名比对，规范化复用 `database.NormalizeSearchText`（与资料库搜索同一口径）；相等或一方包含另一方（被包含方至少两个字符）即不矛盾。结论一个名称都没有、或书没有系列名时无从比对，状态不变。理由：历史推导出的结论别名为空、来源名常与 ComicInfo 差一个副标题或版本后缀，用包含关系压住误报；完全无关的名称仍会被拦下。判据已写入规格「识别结论与识别状态」一节。
- **上报形态**：矛盾时记一条 `class = recheck`、`raised_by = system`、分类 `new_book_contradiction` 的上报，理由写书名和系列名；同一系列已有未处理的复核上报就不再重复记。识别结论与系列元数据不动。
- **挂点**：扫描器在每个批事务提交后，把新增书经装配注入的 `Scanner.SetAddedBooksHook` 同步交给 `identification.Service.RecheckNewBooks`（`bootstrap.Open` 接线）。整库、单系列、监听和委托扫描都经过同一个写入器，所以都会检查；取消后已提交的批次也照样检查。检查自己开一个短事务，出错只记 warn 日志。书快照读不出来时不报告任何新书，避免把旧书当新书。
- **扫描保护（用户决定的实现）**：已有系列加入带 ComicInfo 的书时，扫描在批事务内重读系列当前行和字段来源记录，不再用扫描开始时的缓存；`seriesmeta.SourceBacked` 认定当前值仍等于来源记录值的标量（来源不是升级回填的 `manual`），与锁定字段一样保留当前值，但不加锁。评分按记录原值或提案写入时的一位小数比较。顺带的效果：扫描期间的人工编辑、补充和锁不会再被扫描开始时的旧缓存回退。

# 07: 识别后的元数据补充

**What to build:** 识别一经确认，服务端立即按固定策略为该系列补充元数据，并把该系列积压的旧提案以「被识别取代」结案。agent 不必再逐字段组装写入请求。

**Blocked by:** 02 元数据补充与证据来源解耦；06 主循环：领取与提交裁决

**Status:** done

- [x] 识别确认后，在同一项系列操作里完成补充，并留下与现有补充相同的收据，可以用现有工具查询、撤销和清理。本票覆盖 agent 提交的路径，同时提供一个可供人工确认复用的同一用例。
- [x] 文本字段（标题、简介、出版社、状态）按可配置的来源优先级取第一个有值的，默认顺序为 Bangumi > AniList > MangaDex > MyAnimeList > Comic Vine。Bangumi 的标题取中文名，没有中文名时取原名。
- [x] 只补空值：非空值和锁定字段都不变。
- [x] 标题占位例外：
  - 当前标题与目录名完全一致时，可以替换为来源标题；
  - 替换后保留锁，重扫不会改回目录名；
  - 与目录名不同的标题受保护。
- [x] 综合评分只在缺失时生成：对所有已识别来源的有效评分换算成十分制后等权平均，并保留原始分数、尺度和公式。新来源的识别到达时，如果当前评分仍是公式算出的且没被人改过，就重新计算。
- [x] 来源链接取所有已识别来源的并集。作者以优先级最高的来源为准，其它来源只补充缺失的角色。
- [x] 本票不追加标签，标签由 08 接上；封面不随识别变化。
- [x] 该系列的待审旧提案以「被识别取代」结案：在写入事务内重读待裁决状态（ADR 0011），结案状态能与驳回、已应用区分开。
- [x] 集成测试覆盖：优先级取值、中文名、标题占位、锁定保护、评分重算、链接并集、旧提案结案、撤销。
- [x] 后端门禁通过，生成契约无漂移。

## Comments

**用户决定（2026-11-25）**：扫描不覆盖、不清空「当前值有来源记录且与记录值一致」的字段（由票 14 在扫描侧实现）。所以识别补充写入的每个字段都必须写字段来源记录，否则下一本带 ComicInfo 的新书入库时会被冲掉。

本票按规格「留给实施决定的工程细节」自己定下的取值：

- **事务与用例形状**：识别与补充在同一个写事务里提交。共用用例是 `identification.Service.confirm`：写结论后调 `enrichment.Service.EnrichIdentified(ctx, tx, …)`，agent 提交走它，人工确认（12、13）也复用它。补充写失败时整条裁决回滚，以 `unavailable` 报告，重试是安全的。理由：已识别的系列不会再被领取，拆成两个事务的话，补充一旦失败就永远补不上。没有复用 02 的 `applyEvidence` + `decision`：识别策略逐字段跳过锁定和非空字段，不把整个系列判冲突，而且必须和裁决同事务。
- **持久化结构**：`identification_conclusions` 加 `facts` 列，保存确认时证据包里该候选的来源快照。每次补充都按该系列全部结论的快照取值。历史推导出的结论为 `{}`，只贡献条目链接。
- **收据**：kind 仍是 `enrich`，撤销、查询、清理全部沿用。新增 `identification{entries, placeholder_title, superseded_proposals}`，已纳入生成契约。请求键为 `identify-` 加「凭据、请求键、系列」sha256 的前 16 字节（hex）：一个提交请求键覆盖整批，而收据键按凭据唯一。裁决结果加 `operation_id`，提交工具描述里写明了 identify 会补元数据、可凭它撤销。每个字段的证据只留该字段用到的来源值和条目身份，不存整份快照：每个识别的系列都会留一张收据，六万个系列累计起来体积可观。
- **来源优先级配置**：`identification.source_priority`，默认 bangumi、anilist、mangadex、myanimelist、comicvine。没列出的来源按默认顺序接在后面；未知键在配置校验里报错；即时生效。
- **文本取值**：标题取来源的 Title，为空时取 OriginalTitle（Bangumi 的 Title 本来就是中文名、没有时回落原名）。状态经 `NormalizeStatusCodeOptional` 归一，认不出或为 unknown 时算无值，继续看下一个来源。
- **「公式评分且没被人改过」的判据**：rating 的字段来源记录指向的操作收据里，rating 带公式并且实际改过；记录值等于当前值。人工编辑不写来源记录，值一变就不再重算。
- **来源链接**：链接名用来源显示名（Bangumi、AniList、MangaDex、MyAnimeList、Comic Vine），与提案应用写的一致。同 URL 或同名（不区分大小写）的链接已存在就不再加。
- **结案**：新终态 `superseded`（`proposal.SupersedePending`），在补充事务内对该系列全部待审提案逐条走 pending CAS。存量推导在同一个事务里，对推导出识别的每个系列做同样的结案（见下方用户决定）。
- **作者**：角色按去首尾空白、不区分大小写比较；系列现有作者中没有角色的条目不占任何角色。补进的作者和其它字段一样写来源记录、进收据、可撤销。
- **撤销占位标题**：收据记了 `placeholder_title` 时，撤销可以越过标题锁恢复目录名，锁照旧保留；别的锁照常拦撤销。
- **测试接缝**：除下面这一条以外都在 bootstrap 接缝上测（MCP 提交、管理员 HTTP、真实扫描）。「新来源到达时重算公式评分」目前没有公开入口能给已识别系列追加来源，所以在 `enrichment.EnrichIdentified` 入口用真实 SQLite 测；12、13 接上人工确认后，应在 bootstrap 接缝补一条端到端用例。

**用户决定（2026-11-25）**：

- 作者按角色补空：系列已有的角色不动，只补系列缺少的角色。取值按来源优先级，以最高优先级来源为准，其它来源只补仍然缺的角色。
- 存量积压在升级时一并结案：存量推导出已识别的系列，其它从没被接受过的待审提案，在升级推导时以 `superseded` 结案。结案行保留，可以和驳回区分；在写入事务内重读待裁决状态（ADR 0011）；重复执行结果不变。03 里断言它们保持待审的测试已相应改掉。

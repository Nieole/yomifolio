# 07: 识别后的元数据补充

**What to build:** 识别一经确认，服务端立即按固定策略为该系列补充元数据，并把该系列积压的旧提案以「被识别取代」结案。agent 不必再逐字段组装写入请求。

**Blocked by:** 02 元数据补充与证据来源解耦；06 主循环：领取与提交裁决

**Status:** ready-for-agent

- [ ] 识别确认后，在同一项系列操作里完成补充，并留下与现有补充相同的收据，可以用现有工具查询、撤销和清理。本票覆盖 agent 提交的路径，同时提供一个可供人工确认复用的同一用例。
- [ ] 文本字段（标题、简介、出版社、状态）按可配置的来源优先级取第一个有值的，默认顺序为 Bangumi > AniList > MangaDex > MyAnimeList > Comic Vine。Bangumi 的标题取中文名，没有中文名时取原名。
- [ ] 只补空值：非空值和锁定字段都不变。
- [ ] 标题占位例外：
  - 当前标题与目录名完全一致时，可以替换为来源标题；
  - 替换后保留锁，重扫不会改回目录名；
  - 与目录名不同的标题受保护。
- [ ] 综合评分只在缺失时生成：对所有已识别来源的有效评分换算成十分制后等权平均，并保留原始分数、尺度和公式。新来源的识别到达时，如果当前评分仍是公式算出的且没被人改过，就重新计算。
- [ ] 来源链接取所有已识别来源的并集。作者以优先级最高的来源为准，其它来源只补充缺失的角色。
- [ ] 本票不追加标签，标签由 08 接上；封面不随识别变化。
- [ ] 该系列的待审旧提案以「被识别取代」结案：在写入事务内重读待裁决状态（ADR 0011），结案状态能与驳回、已应用区分开。
- [ ] 集成测试覆盖：优先级取值、中文名、标题占位、锁定保护、评分重算、链接并集、旧提案结案、撤销。
- [ ] 后端门禁通过，生成契约无漂移。

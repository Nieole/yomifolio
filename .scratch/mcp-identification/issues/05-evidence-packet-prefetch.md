# 05: 证据包预取（手动回填）

**What to build:** 所有者手动启动预取后，服务端在后台为未处理的系列做多来源搜索，把本地线索和候选整理成证据包持久保存。网页上原有的全库、资料库两个批量刮削入口，改为启动预取。

**Blocked by:** 01 多来源搜索扇出成为可复用能力；03 识别结论与识别状态

**Status:** done

- [x] 预取作为一次普通运行出现在任务中心，有进度，可以暂停和取消。中断后再次发起时，从还没有可用证据包的系列继续。
- [x] 只处理未处理的系列。已识别、已审定、待人工的系列不预取。
- [x] 搜索词由服务端确定性地生成多个变体：先清洗目录名中的卷号、汉化组、方括号标签等噪声，再加入 ComicInfo 的系列名与作者。

- [x] 各来源的限速由服务端统一控制，测试配置可以关闭限速。单个来源失败时记为不可用，其它来源的候选照常保存。

## Comments

本票按规格「留给实施决定的工程细节」自己定下的取值（都不碰已确认的产品或安全边界）：

- **持久化结构**：`identification_evidence` 表，每系列一行、整包替换，随系列级联删除。`packet` 是给 agent 与所有者看的文本视图；`source_facts` 按候选 id 保存校验过的来源快照，留给 07 补充取值。读取时再按当前的排除候选过滤一次，抓取之后才否决的条目也不会出现。
- **候选 id**：`<来源>:<条目编号>`，条目编号走 `identification.EntryOf`，和识别结论、排除候选的命名一致。定位不到条目的来源结果不进包。
- **搜索词清洗与变体**：
  - 清洗：去掉方括号、圆括号、花括号等括号段；书名号只去符号、保留内容。再去掉卷号与话数标记（第 N 卷、全 N 卷、Vol./v/ch.、结尾的 N-M 区间和带前导零的数字），以及含「汉化/翻译/扫图/嵌字」、以 scans 结尾的组名词和「完结/全彩/单行本」这类版本词。整个名字都在括号里时，退回括号里的内容。
  - 变体按顺序生成：清洗后的目录名；清洗后的 ComicInfo 系列名；系列名（没有时用目录名）加 ComicInfo 第一作者。按规范化文本去重，单个词不超过 100 字。
- **候选取舍与比对信号**：
  - 每个词向每个来源取前 5 条。合并去重后，标题与本地名称一致的排在前面，每个来源留 3 条。
  - `title_matches`：候选标题或原名规范化后，等于清洗后的目录名或 ComicInfo 系列名。
  - `author_matches`：ComicInfo 编剧、作画与候选作者规范化后有交集；任一侧没有作者时不给这一项。
  - `source_volumes`、`local_books`：直接给出两个数，不作比较。
- **证据包字节预算**：单包 JSON 不超过 4 KiB。简介摘要 60 字，标题 100 字，作者最多 3 位、每位 40 字，文件名取前 3 本。超出预算时先去掉摘要，再从排名靠后的候选删起。整批领取的响应预算由 06 在此之上控制。
- **来源不可用**：某个来源对所有搜索词都失败，记为 `unavailable`。没有任何来源应答的系列不存包，在运行里记一条失败，保持待预取，下次发起时会再试。
- **ComicInfo 读取**：取前 3 本书里第一份可读的 ComicInfo.xml，以 MetadataScan 磁盘作业的身份在运行里读取。`parser.ComicInfo` 增加了 `Year` 字段。
- **各来源限速**：配置项 `identification.source_intervals_ms` 设定同一来源两次请求的最小间隔。
  - 默认值：Bangumi 1000、AniList 2000、MangaDex 1000、MyAnimeList 1000、Comic Vine 18000 毫秒。
  - 0 取默认值，负数不限速，修改即时生效。
  - 进程内所有预取运行共享同一份节拍。
- **任务与可续跑**：
  - 任务类型 `evidence_prefetch`，变体 `all_libraries`（系统作用域）和 `one_library`（资料库作用域）。
  - 可重试，不可续跑：无人值守时自动重启，会对外部站点连发一长串没人要求的请求，这与刮削的先例一致。
  - 扫描收尾串联的变体由 15 决定。
- **管理员接口**：
  - `POST /api/identification/prefetch` 接受 `{"library_id": n}`，空体表示全库；响应 `{run_id, series}`，`series` 为 0 时不建运行。
  - `GET /api/identification/series/{id}` 增加 `evidence` 字段。
  - 原来的 `POST /api/libraries/{id}/scrape`、`POST /api/system/batch-scrape`，以及 `scrape` 任务的发起函数和重启函数都已删除，网页上的两个入口改调新接口。任务中心里已有的 `scrape` 运行照常显示，但不能再重试，这样就不会再产生取第一条结果的提案。
- **MCP 进度**：`library_identification_progress` 的结果增加 `prefetch: {ready, pending}`，只统计未处理的系列。

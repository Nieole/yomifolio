# MCP 系列识别与批量整理

Status: ready-for-agent

## Problem Statement

我的藏书有 62,960 个系列、682,641 本书、约 2,361 万页、9.6TB；每周新增几十本书，大多是已有系列追加新书。

**旧的整理方式让我自己成了瓶颈。** 系统按目录名去 Bangumi 搜索，取第一条结果生成提案，再由我逐条审核。首轮扫描后审核还剩 700 多条积压。批量刮削会把我已经处理过的系列重新走一遍，所以我停用了它，之后新增的系列都没有刮削过。真正缺元数据的系列远比积压的提案多，靠人工审核在这个量级和持续增量下做不完。

**首版 MCP 没能把这件事交给 agent。** 我用本机的 qwen3.8-flash-next q2 量化模型，经 ThinkRail 接入 pi，在一个只有 4 个系列的测试资料库上跑了快两个小时，一条元数据都没写进去。agent 在这些地方卡住了：

- 读不到工具结果，只好改用 bash 和 curl 直接调 HTTP；
- 想找「缺元数据的系列」，结果是空的，因为缺失字段过滤要求所列字段**全部**缺失才命中；
- 看不懂「身份/版本确认」是什么意思，转去仓库里读规格；
- 把「对象不存在」误判成权限问题；
- 工具太多、描述太长，上下文被反复压缩，计划丢失；
- 不知道有权限就可以直接写，停下来准备请示我；
- 搜索词要它自己拼。

即使换成更强的模型，问题也只是缓解，不会消失：
- 一个系列要七八次工具调用，所有组装工作都压在 agent 身上；
- 系统不记得一个系列已经处理过、结论是什么，被上报或查无此作的系列每一轮都会被重新捞出来；
- 扫描时标题被设成目录名并锁定，补充规则「锁定不动、非空不改」使识别永远补不上标题，6 万多个系列会一直显示目录名。

## Solution

系统按「系列 × 来源」持久记住**系列识别**：哪个系列对应哪个来源的哪个条目。由这些结论推导出每个系列的**识别状态**，未处理、已处理、要我看的，一查就知道。

- **服务端**预先替所有未处理的系列多来源搜索，把本地线索和候选整理成**证据包**保存下来。
- **agent** 一次领取一批证据包，只回答每个系列「是哪一部」「查无此作」，或者**上报**给我。
- **识别确认后**，服务端按固定策略补充元数据：空字段才填、标签过滤后追加、评分按公式算、占位标题换成来源标题。
- **agent 判断有误时**，可以在受限边界内纠正自己的识别和来源带来的字段，但永远碰不到我改过的东西。
- **我**只处理上报和待复核的系列；不想让流程碰的系列，可以设为**已审定**。
- **历史记录**会被沿用：我以前应用过的提案算作已识别，驳回过的条目不会再被选中，积压的提案在识别完成后自动结案。

MCP 工具面收缩成一个四步主循环加若干原语，目标是本机的弱模型不读仓库也能走完。决策理由见 ADR 0017（draft）。

## User Stories

1. 作为资料库所有者，我希望 agent 只把拿不准的系列交给我，以便六万个系列的整理不再需要我逐条审核。
2. 作为资料库所有者，我希望每个系列的识别结论被持久记住，以便已处理的系列不会在下一轮被重新处理。
3. 作为资料库所有者，我希望新出现的系列自然处于未处理状态，以便增量整理不需要记住上次处理到哪里。
4. 作为资料库所有者，我希望已识别系列追加新书时不被重新识别，以便连载追加不制造重复工作。
5. 作为资料库所有者，我希望新书的本地线索与识别结论矛盾时，系列被标为待复核，以便错误识别能被发现。
6. 作为资料库所有者，我希望系列进入待复核时，原识别带来的字段保持不动，以便我复核之前内容不会被删掉。
7. 作为资料库所有者，我希望资料库路径迁移后识别结论原样保留，以便换盘不会让整理工作重来。
8. 作为资料库所有者，我希望随时看到各识别状态下有多少系列，以便知道整理进展到哪里。
9. 作为资料库所有者，我希望手动启动一次存量证据包预取，以便六万个系列的候选能在后台慢慢备好。
10. 作为资料库所有者，我希望预取作为一次普通运行出现在任务中心，可以暂停、取消，并能看到进度，以便它不会悄悄占用网络和磁盘。
11. 作为资料库所有者，我希望预取中断后再次发起时，从还没备好的系列继续，以便已经搜过的系列不会重新搜索。
12. 作为资料库所有者，我希望扫描结束后，服务端自动为新出现的未处理系列低优先级预取，以便新系列很快可以被领取，而不需要我再按一次按钮。
13. 作为资料库所有者，我希望预取遵守各来源的限速，以便不会因为批量搜索被来源站封禁。
14. 作为资料库所有者，我希望单个来源失败时其它来源的候选照常保存，以便一个来源宕机不会让整批证据包作废。
15. 作为 agent 操作者，我希望一次领取一批系列及其证据包、一次提交整批裁决，以便每个系列不再需要七八次调用。
16. 作为 agent 操作者，我希望领取时直接拿到服务端保存的证据包，以便不用等待搜索，证据也不会在处理途中过期。
17. 作为 agent 操作者，我希望证据包过旧时，服务端在领取时安排刷新，以便我不会基于很久以前的来源数据做判断。
18. 作为 agent 操作者，我希望搜索词由服务端根据目录名和 ComicInfo 生成，以便不必自己清洗目录名噪声。
19. 作为 agent 操作者，我希望每个候选附带可核对的比对信号，例如标题是否一致、作者是否与 ComicInfo 一致、卷数与本地书数，以便弱模型也能判断，而不必解读来源可信度。
20. 作为 agent 操作者，我希望证据包只含文本、体积受控，以便上下文有限的本地模型也能一次处理一批。
21. 作为 agent 操作者，我希望人否决过的条目根本不出现在证据包里，以便我不会重复犯人已经纠正过的错误。
22. 作为 agent 操作者，我希望多个会话并行领取时不会拿到同一批系列，以便可以同时开多个 agent。
23. 作为 agent 操作者，我希望领取后中断的系列在租约到期后自动退回，以便崩溃的会话不会永久占住系列。
24. 作为 agent 操作者，我希望没有可领取的系列时，响应说明原因（全部处理完，还是预取未就绪），以便我知道该停下还是稍后再来。
25. 作为 agent 操作者，我希望同一请求重放时返回原来的结果，以便断线重试不会重复写入。
26. 作为 agent 操作者，我希望一次裁决可以把一个系列同时识别到多个来源，以便多来源字段能一起补齐。
27. 作为 agent 操作者，我希望整批提交时逐个系列报告结果，以便一个系列失败不会掩盖其它系列的成功。
28. 作为 agent 操作者，我希望对难判的系列用自定义搜索词重搜，并把结果并入它的证据包，以便目录名噪声严重时也能找到条目。
29. 作为 agent 操作者，我希望按需查看本地封面、指定页缩略图和候选封面，以便有视觉能力的模型能区分相似候选。
30. 作为资料库所有者，我希望候选封面只从已知来源域名拉取并缩成小图，以便图片能力不会变成任意抓取网址的通道。
31. 作为资料库所有者，我希望查无此作的结论记录搜过哪些来源，以便新启用来源时只对新来源重试。
32. 作为资料库所有者，我希望识别确认后服务端自动补充元数据，以便 agent 不必逐字段组装写入请求。
33. 作为资料库所有者，我希望文本字段按可配置的来源优先级取值，Bangumi 标题优先取中文名，以便多来源识别时结果可预期、贴近我的藏书语言。
34. 作为资料库所有者，我希望综合评分对所有已识别来源等权计算，并在新来源识别到达时重算由公式得出的评分，以便评分随证据增加而完整，又不覆盖我自己的评分。
35. 作为资料库所有者，我希望来源标签经投票阈值、黑名单和数量上限过滤后才追加，以便「漫画」「日本」「已购」这类噪声标签不进入藏书。
36. 作为资料库所有者，我希望来源链接取所有已识别来源的并集，以便能回到每个来源查看原始资料。
37. 作为资料库所有者，我希望扫描生成的目录名标题在识别后被来源标题替换，人改过的标题不被替换，以便系列不再显示目录名。
38. 作为资料库所有者，我希望标题替换后仍保持锁定，以便重新扫描不会把它改回目录名。
39. 作为资料库所有者，我希望封面不随识别自动替换，以便封面只在 agent 明确比较后才改善，人工封面永远受保护。
40. 作为资料库所有者，我希望 agent 能撤换自己做出的错误识别，并撤回该识别带来、之后未被改动的字段，以便错误能被干净地纠正。
41. 作为资料库所有者，我希望 agent 能改正来自来源且之后未被人改过的字段，并留下原因和可撤销的收据，以便来源本身的错误数据也能修正。
42. 作为资料库所有者，我希望人工编辑过的值、ComicInfo 导入的值、锁定字段、人工封面和人确认的识别永远不被 agent 改动，以便我的工作不会被自动流程覆盖。
43. 作为资料库所有者，我希望 agent 怀疑人确认的识别有误时，只能把系列上报为待复核，以便最终决定仍在我手里。
44. 作为资料库所有者，我希望 agent 的作者校正与封面改善作为独立操作保留，并沿用现有的系列内校正与封面保护规则，以便需要判断的改动仍然可控。
45. 作为资料库所有者，我希望每次由识别触发的补充都留下与现有补充相同的收据，可以查询、撤销和清理，以便审计和撤销不需要第二套机制。
46. 作为资料库所有者，我希望我否决过的条目不再被识别为该系列，以便同样的错误不会重复出现。
47. 作为资料库所有者，我希望历史上已应用的提案被视为人工确认的识别，以便过去的裁决不被重做。
48. 作为资料库所有者，我希望历史上被驳回的提案条目被视为排除候选，以便旧流程里否决过的错误不会被 agent 再选一次。
49. 作为资料库所有者，我希望积压的待审提案在系列被识别后以「被识别取代」结案，并能与驳回区分，以便积压自然清空，历史也不失真。
50. 作为资料库所有者，我希望存量推导可以重复执行而结果不变，以便升级中断后重跑是安全的。
51. 作为资料库所有者，我希望把系列设为已审定、随时可撤回，以便识别流程不再领取或补充它。
52. 作为资料库所有者，我希望在一个页面处理所有识别类上报和待复核系列：挑候选、否决候选、判查无此作、自定义重搜或设为已审定，以便要我做的事集中在一处。
53. 作为资料库所有者，我希望在待人工页挑中候选后，系列立即记为人工确认并补充元数据，以便我的一次点击就能完成整理。
54. 作为资料库所有者，我希望待人工页显示证据包和 agent 写的理由，以便我不用自己重新搜索也能判断。
55. 作为资料库所有者，我希望目录分组、重复和标签类上报以备注形式出现在同一页面，可以关闭，并且不阻塞识别，以便这些问题不会拖住元数据整理。
56. 作为资料库所有者，我希望按上报分类筛选待人工页，以便一次集中处理同一类问题。
57. 作为资料库所有者，我希望在系列详情页看到各来源的识别结论、确认者、确认时间和条目链接，并能撤换识别或设为已审定，以便单个系列的来龙去脉一目了然。
58. 作为资料库所有者，我希望在系列详情页撤换识别时，旧条目自动记为排除候选，以便它不会再被 agent 选回来。
59. 作为资料库所有者，我希望按识别状态筛选资料库，例如筛出所有查无此作的系列，以便能针对某类系列集中处理。
60. 作为资料库所有者，我希望单系列手动搜索时挑中的条目直接记为人工确认的识别，以便手动整理与 agent 整理落在同一份结论里。
61. 作为资料库所有者，我希望批量刮削入口改为启动证据包预取，以便不再批量产生首条结果提案。
62. 作为资料库所有者，我希望只读 agent 能巡检重复、目录分组和标签问题并上报，但不能改动任何内容，以便可以放心让它全库巡检。
63. 作为资料库所有者，我希望普通用户的凭据只能读取和上报，以便凭据不会让普通账号获得写入能力。
64. 作为 agent 操作者，我希望能跨资料库按名称和识别结论查找疑似重复的系列，以便提供重复上报的依据。
65. 作为 agent 操作者，我希望能在系列上添加作品群关系，并且可以撤销，以便续作、外传等关系也能由 agent 整理。
66. 作为 agent 操作者，我希望连接时就得到一段主循环说明（领取 → 提交 → 难判上报，有权限即可直接写），以便不需要读仓库或请示人。
67. 作为 agent 操作者，我希望工具描述简短并附调用示例，以便弱模型能从描述直接写出正确调用。
68. 作为 agent 操作者，我希望被拒绝时得到下一步提示，又不泄露对象是否存在，以便能自行纠正参数。
69. 作为 agent 操作者，我希望每个工具结果都有可读的文本副本，以便只读取文本内容的客户端也能工作。
70. 作为 agent 操作者，我希望缺失字段过滤在任一所列字段缺失时即命中，以便「找缺元数据的系列」得到符合直觉的结果。
71. 作为 agent 操作者，我希望工具清单只列出当前凭据可用的工具，以便不会在用不了的工具上浪费上下文。
72. 作为资料库所有者，我希望 MCP 不再暴露细粒度识别链和内部模型额度工具，以便工具面只保留 agent 真正需要的能力。
73. 作为资料库所有者，我希望已有的内部模型额度记录保留不删，以便下线工具不会抹掉历史数据。

## Implementation Decisions

### 要新建或修改的模块

- **新增应用层识别模块**，与现有的委托访问模块、补充模块并列。它负责识别结论、识别状态推导、证据包、领取租约、提交裁决、纠正和上报。它复用委托访问模块的当前授权与运行检查点，补充写入复用补充模块的收据、撤销和清理机制，不另造第二套。
- **委托访问模块**：多来源搜索的来源范围、搜索结果快照的校验规则迁移给证据包预取复用；内存中有过期时间的搜索证据随细粒度识别链一起下线。
- **补充模块**：增加「按识别结论补充」的入口，接受由策略产生的字段选择，不再要求调用方逐字段提供期望值快照；期望值校验在服务端内部完成。作者校正和封面改善从逐系列补充命令中拆出，成为独立的用例入口。
- **系列元数据模块**：增加标题占位例外。系列当前标题与目录名完全一致时，识别补充可以替换它，替换后保留锁。其它补空、锁定和集合追加规则不变。
- **提案模块**：增加「被识别取代」终态，与驳回、已应用、补充后关闭可以区分；结案在写入事务内重读待裁决状态，遵守 ADR 0011。
- **元数据来源**：Bangumi 结果保留标签投票数，供标签策略使用。
- **任务与运行**：新增证据包预取任务类型。预取可以重试。按词汇表判据定下（票 15）：
  - 扫描收尾串联的低优先级预取是这个任务的**另一个变体**（资料库作用域的增量预取），不是对手动回填的合并发起。它与回填同时跑是可以接受的：两者共用各来源的限速节拍，总请求速率不变，各自跳过对方已备好的系列；并成同一身份的话，新系列要排在持续数天的回填后面。同一资料库的两次增量发起是同一身份，排队时合并不丢东西，因为要处理的系列记在持久的请求里，运行开始时才读取，没有重启入参。
  - 增量预取**可续跑**，手动回填不可续跑。增量预取本来就是无人值守发起的（扫描收尾、领取），工作量限于请求过的系列，不花钱，再发起一次只会把没做完的做完；回填是人对整个藏书的一次决定，无人看着时续跑会连发数天没人要求的外部请求，与刮削的先例一致。
- **MCP 协议适配层**：新增主循环工具和原语，下线细粒度识别链和内部模型额度工具，整改契约（见下文）。
- **管理员网页 HTTP 接口**：增加待人工列表及其处理操作、系列识别结论的读取与撤换、已审定的设置与撤回、启动预取。现有的批量刮削入口改为启动预取。
- **前端**：新增待人工页；在系列详情页加识别区；在资料库筛选条件里加识别状态；手动搜索弹窗改为记录人工确认的识别。新的响应结构纳入生成契约。
- **组装层**：`bootstrap.Options` 增加一个只供识别模块使用的当前时间来源，生产环境用真实时钟。这是为了测试租约到期和证据包过期新开的唯一接缝。

### 识别结论与识别状态

- 识别结论按「系列 × 来源」保存，内容包括：来源条目、确认者类别（人，或 agent 及其凭据归属）、确认时间、一句可核查的理由，以及来源条目的原名与别名。一个系列可以同时识别到多个来源。
- 识别状态由结论推导，不单独编辑，取值为：未处理、已识别、待人工、待复核、查无此作、已审定。
- 查无此作要记录判定时搜过的来源；之后新启用的来源只让该系列对这个新来源重新变为可处理。「新启用」指判定之后经配置启用、判定没有搜过的来源；判定时已启用但不可用的来源不算。重开的系列回到未处理，领取时按下文规则只对新来源刷新证据包；再判查无此作时，搜过的来源取前后两次的并集，识别到新来源则不再保留查无此作。
- **排除候选**随系列保存，只由人的否决产生，包括：人撤换或撤回识别、历史驳回、在待人工页否决。证据包不含排除候选，提交裁决也拒绝它们。所有者在手动搜索里亲手挑中排除候选时，排除解除、照常记为人工确认的识别（用户决定，票 13）。
- **已审定**由人设置、可以撤回。设置后 agent 不会领取该系列，识别流程也不为它补充元数据。
- 不设常驻 agent，也不在扫描后把系列推给 agent。agent 按识别状态拉取，增量不需要水位。
- 系列加入新书不影响已有识别。新书的本地线索与识别结论矛盾时，例如 ComicInfo 系列名指向另一部作品，系列转为待复核，原识别带来的字段保持不变。矛盾判据（票 14 定）：
  - 只看扫描**新加入**、扫描开始前就已存在的系列的书；改名重连的书、强制重扫重读的旧书都不算新书。
  - 线索是新书 ComicInfo 的系列名。没有系列名（或规范化后为空）就是没有线索，状态不变。
  - 只检查至少有一条识别结论的系列；已审定的系列、已有未处理复核上报的系列跳过。
  - 系列名与该系列**所有来源**识别结论的标题、原名、别名逐一比对，比对前用资料库搜索的规范化（全半角、大小写折叠，去掉空白和标点）。与任一名称相等，或一方包含另一方（被包含的一方至少两个字符），就不矛盾；都不满足才算矛盾。结论里一个名称都没有时无从比对，不算矛盾。
  - 判为矛盾时由系统记一条复核类上报（分类 `new_book_contradiction`，理由写明书名和系列名），不改识别结论和系列元数据。检查只读本地数据，在扫描每批提交后同步执行，出错只记日志，不让扫描失败。
- 扫描保护带来源记录的值（用户决定）：已有系列加入带 ComicInfo 的书或强制重扫时，标量字段的当前值与它的字段来源记录一致（提案应用或元数据补充写入、之后没人改过；升级回填的 `manual` 记录不算）就保留，不覆盖也不清空，也不为此加锁；没有这样的来源记录的字段照旧由 ComicInfo 覆盖。判断用批事务内重读的当前行，不用扫描开始时的缓存。
- 资料库路径迁移保留系列身份，识别结论随之保留；系列被删除时，它的识别结论一并删除。
- 持久化的逻辑需求包括：识别结论、排除候选、上报及其处理结果、已审定、证据包及其抓取时间、领取租约。表名和存储布局实施时决定。

### 存量初始状态

升级时一次性从历史推导，可以重复执行而结果不变：
- **已应用的提案**：转为对应来源的人工确认识别，条目取自提案的来源标识。
- **被驳回的提案**：对应条目记为排除候选，系列保持未处理。
- **待审提案**：系列保持未处理。该系列识别完成后，这些提案以「被识别取代」结案。
- **其余系列**：一律未处理。识别补充只填空值、不覆盖人改过的值，所以人工整理过的系列被重新处理也不会损失内容；不想让流程触碰的系列，由人设为已审定。

### 证据包与预取

- **预取是后台运行。**
  - 存量回填由人手动启动，可以暂停和取消；中断后再次发起时，从还没有可用证据包的系列继续。
  - 扫描收尾串联一次低优先级预取，只处理新出现的未处理系列。「新出现」指这次扫描创建的系列；升级前就有、还没有证据包的系列留给手动回填。整库、监听、定时和 agent 经 MCP 发起的委托扫描都串联（用户决定），只处理该次扫描所在资料库；扫描被取消时不串联，部分归档失败时照常串联。「低优先级」指：扫描结束后才发起，不拖慢、也不会让扫描失败；与其它预取共用各来源的限速，不提高任何来源的请求速率；读 ComicInfo 走后台磁盘作业，阅读优先。
  - 领取时如果证据包抓取时间已经超过 30 天，就安排后台刷新。**刷新期间这个系列暂不发放**：领取跳过它，把它交给增量预取刷新，同一批照常发放其它证据包仍有效的系列；全部系列都在等预取或刷新时，空批原因是「预取未就绪」。理由是 agent 不该基于很久以前的来源数据做判断。刷新重新搜索派生词和证据包里记下的自定义重搜词，自定义重搜的结果因此保留。
  - 各来源限速由服务端统一控制，测试配置可以把限速关掉。
- **参与搜索的来源**沿用现有多来源搜索的范围：Bangumi、AniList、MangaDex，以及配置了凭据的 MyAnimeList 和 Comic Vine；不含 LLM。单个来源失败时，该来源记为不可用，其它来源的候选照常保存。
- **搜索词**由服务端确定性生成多个变体：清洗目录名中的卷号、汉化组、方括号标签等噪声，再加上 ComicInfo 的系列名和作者。人或 agent 可以对单个系列用自定义词重搜，结果并入它的证据包。
- **证据包只含文本。**
  - 本地线索：目录名、书数、前几本书的文件名、ComicInfo 的系列名、作者和年份。
  - 候选：每个来源最多 3 条，包含标题、原名、作者、年份、卷数和简介摘要。
  - 比对信号：附在每条候选上，例如标题规范化后是否一致、作者是否与 ComicInfo 一致、来源卷数与本地书数。它们是可核对的事实，不是匹配概率，与 metadata 规格「来源 confidence 不是身份概率」一致。
  - 排除候选不进证据包。
- **领取**：每批最多 20 个系列，整体响应在约 30 KB 量级。证据包还没就绪的系列不发放。没有可发放的系列时，响应说明是全部处理完毕还是预取未就绪。

### 识别后的元数据补充

识别确认后，无论由 agent 还是人确认，服务端都在同一项系列操作里补充元数据，并留下与现有补充相同的收据，可以查询、撤销和清理。
- **文本字段**（标题、简介、出版社、状态）按来源优先级取第一个有值的。默认顺序是 Bangumi > AniList > MangaDex > MyAnimeList > Comic Vine，可在配置里调整。Bangumi 标题取中文名，没有中文名时取原名。
- **综合评分**仍只在缺失时生成：对所有已识别来源的有效评分换算成十分制后等权平均，保留原始分数、尺度和公式。新来源识别到达时，如果当前评分仍是公式算出的、且没被人改过，就重新计算。
- **标签和来源链接**取所有已识别来源的并集，只追加。标签依次通过三道过滤：来源投票数阈值、可配置的黑名单（媒介、地区、年份、个人状态等）、每个系列的追加上限。阈值、黑名单和上限的默认值实施时决定。
- **作者**以优先级最高的来源为准，其它来源只补充缺失的角色。
- **标题占位例外**：系列当前标题与目录名完全一致时，视为扫描生成的占位值，可以替换为来源标题，替换后保留锁。标题与目录名不同，就视为人改过，受保护。
- **封面**不随识别自动替换。

### 纠正边界

agent 可以做：
- **撤换识别**：只限 agent 确认的识别。服务端撤回旧识别带来、之后没被改动的字段（沿用现有撤销的期望值校验），再按新识别补充。
- **改正字段**：只限当前值有来源记录、并且来源记录中的值与当前值一致的字段。每次改正都要写原因、留收据，可以撤销。
- **作者校正与封面改善**：作为独立操作保留，沿用现有的系列内作者校正规则，以及「只改未锁定的归档自动封面」规则。

agent 不能做：
- 改动人工编辑过的值、ComicInfo 导入的值（这两类都没有来源记录）、锁定字段、人工封面。标题占位例外只由服务端执行，不对 agent 开放。
- 撤换人确认的识别。agent 只能把系列上报为待复核。

人在网页上撤换识别时，旧条目记为排除候选。

### MCP 工具契约

**主循环**（四个工具）：
1. **领取一批**：可按资料库过滤，每批最多 20 个系列，返回证据包和租约。租约到期后，未提交的系列退回未处理。租约时长实施时决定。
2. **提交裁决**：每个系列一条，取值为「识别为某来源的某候选」（一次可以识别多个来源）、「查无此作」或「上报」（带分类），并附一句理由。结果逐系列返回，不保证整批原子；同一请求键重放时返回原结果。
3. **重搜单个系列**：使用自定义搜索词，结果并入该系列的证据包。
4. **查看进度**：返回各识别状态下的系列数和预取情况。

**原语**（不在主循环里）：
- 撤换识别、改正字段、作者校正、封面改善。
- 取识别图片：本地封面、指定的 1–3 页缩略图，以及证据包候选的封面。候选封面由服务端只从已知来源域名拉取并缩小，沿用现有图片体积预算。
- 作品群关系写入：作用于单个系列，可以撤销。
- 撤销与收据查询：沿用现有工具。
- 扩展只读：跨资料库按名称和识别结论查重、目录与书名证据、标签统计。
- 上报：带分类。

**上报分类**：
- 识别类：多候选难分、版本不确定、来源无结果但疑似存在。系列会进入待人工。
- 非识别类：疑似目录分组错误、疑似重复、标签问题。只挂备注，不改变识别状态。

**下线**：
- `library_search_sources`、`library_get_source_search`、`library_propose_match`、`library_get_match_proposal`、`library_get_enrichment_state`、`library_enrich_metadata`、`library_enrich_metadata_batch`。其中的作者校正和封面能力迁移到上面的原语。
- `library_assess_match`、`library_get_model_operation` 和 `internal_llm` 能力。已有的额度记录数据保留不删，不再提供查询入口。
- 只有一位所有者使用，所以不设过渡期。

**能力映射**（不新增能力）：
- `metadata_write`：领取、提交、重搜、撤换、改正、作者校正、封面、作品群关系写入、撤销。
- `read`：进度查询、取识别图片、扩展只读、上报。
- 普通用户的凭据仍然只有 `read` 生效。
- `cleanup` 和运行类工具不变。

**契约整改**：
- 每个结果都带 JSON 文本副本。
- 初始化时的 `instructions` 写明主循环：领取 → 提交 → 难判时上报，有权限即可直接写入，无需请示人。
- 每个工具描述控制在约 400 字符以内，并附一个调用示例。
- 拒绝时附下一步提示，但不泄露对象是否存在。
- `library_find_series` 的 `missing_fields` 改为任一字段缺失即命中。
- 工具清单继续按凭据当前的能力过滤。

### 人的界面

- **待人工页**：列出识别类上报和待复核的系列，显示证据包和 agent 写的理由，可以按分类筛选。可做的操作有：
  - 挑候选：记为人工确认，随即补充元数据；
  - 否决候选：记为排除候选；
  - 判为查无此作；
  - 自定义重搜；
  - 设为已审定。

  非识别类上报也列在这一页，处理完可以关闭。
- **系列详情页**：显示各来源的识别结论、确认者、确认时间和条目链接；可以撤换识别，也可以撤回识别（旧条目记为排除候选，撤回它带来、之后没被改动的字段；没有其它识别时系列回到未处理，用户决定，票 13），可以设为已审定或撤回已审定。
- **资料库筛选**：增加识别状态这个条件。
- **单系列手动搜索弹窗**：挑中条目即记为人工确认的识别，并按上面的策略补充。
- **批量刮削入口**（全库和资料库两个）：改为启动证据包预取，不再批量生成取第一条结果的提案。
- 不做抽检视图。

### 与既有决定的关系

- ADR 0017（draft）记录本次取舍。它推翻了 `mcp-library` 规划中「不建立待办、增量水位或维护状态机」的排除项；常驻 agent 和扫描后推给 agent 仍然排除。
- ADR 0016 中内部模型额度委托的部分，随 `internal_llm` 下线而失效。实施交付时，把这一部分标为 deprecated 并链接 ADR 0017；清理自主权部分继续有效。功能实际下线前不改它的状态。
- ADR 0011 继续约束「被识别取代」结案，以及所有由识别触发的写入。
- 长期契约在实施时归还所属规格：领域词汇已经写入领域词汇表；跨模块边界写进架构规格的 MCP 节；用例契约写进 application 模块规格；协议契约写进 api 模块规格。

## Testing Decisions

### 什么是好测试

- 只验证外部可观察的行为：MCP 工具结果、管理员网页接口的响应、公开读取到的系列元数据、识别状态、收据，以及实际读到的封面。
- 不断言私有函数的调用顺序、内部 SQL 或表结构。
- 不靠盲等：时间相关的行为用注入的时钟推进，异步运行用现有的运行查询与等待来同步。

### 接缝

1. **后端主接缝（沿用现有）**：用 `bootstrap.Open` 组装真实服务；官方 Go SDK 作为 MCP 客户端，经真实 HTTP 调用；外加管理员网页的 HTTP 接口。数据用真实的临时 SQLite、资料库和归档。外部来源经 `bootstrap.Options.Sources` 注入替身，替身记录收到的每个搜索词。后端行为都在这一层验证：
   - 存量推导：先写入历史提案，再执行 Open；
   - 扫描串联预取：通过网页 HTTP 触发真实扫描；
   - 搜索词清洗：断言替身收到的搜索词；
   - 补充策略、纠正边界、上报和工具清单：通过公开读取断言。
2. **时钟接缝（新增）**：`bootstrap.Options` 注入的当前时间，只用来推进租约到期和证据包过期。
3. **前端接缝（沿用现有）**：vitest 组件测试，模拟 HTTP。覆盖待人工页、系列详情页的识别区、识别状态筛选和手动搜索弹窗。组件测试不替代真实服务的授权验收。

stdio 代理只转发，工具面变化不需要改动它，它的现有进程测试保持不变。

### 已有先例

- 后端：bootstrap 包里现有的 MCP 集成测试，包括工具清单按能力过滤、运行的断线与重连、补充收据与撤销、清理边界、封面取消；以及 `TestOpenUsesOneManagerQueueAndServesBoundHTTP` 这类共享组装测试。
- 前端：现有的元数据审核并发测试和账户管理测试，它们是权威响应与冲突呈现的先例。

### 核心场景

- **识别状态**：
  - 能从未处理推导出已识别、查无此作、待人工；
  - 已审定的系列不会被领取也不会被补充，撤回后恢复；
  - 新书线索矛盾时转为待复核，原字段保持不变；线索不矛盾时状态不变；
  - 新启用来源后，查无此作的系列只对该来源重新可处理；
  - 路径迁移后识别结论保留。
- **存量推导**：
  - 已应用的提案转为人工确认的识别；
  - 驳回的提案转为排除候选，并且不出现在证据包里；
  - 待审提案在识别后以「被识别取代」结案，可以与驳回区分；
  - 推导重复执行结果不变。
- **领取与租约**：
  - 两个会话并行领取不重叠；
  - 推进时钟后，租约到期的系列退回；
  - 证据包未就绪的系列不发放，并说明原因；
  - 整批提交时部分成功如实报告；
  - 请求键重放返回原结果。
- **预取**：
  - 手动回填可以暂停和取消，再次发起时不重复已完成的系列；
  - 扫描串联的预取只处理新的未处理系列；
  - 推进时钟后，过期的证据包在领取时被刷新；
  - 搜索词变体由目录名和 ComicInfo 生成；
  - 单个来源失败不影响其它来源的候选；
  - 排除候选被剔除。
- **补充策略**：
  - 按来源优先级取值，Bangumi 优先取中文名；
  - 多来源等权评分；新来源到达时只重算公式评分，人改过的评分不动；
  - 标签按投票阈值、黑名单和上限过滤；
  - 来源链接取并集；
  - 标题占位替换后锁保留、重扫不还原；人改过的标题受保护；
  - 锁定字段和非空的人工值不变；
  - 封面不随识别变化。
- **纠正边界**：
  - 撤换 agent 的识别时，撤回未改动的字段并按新识别补充；
  - 人确认的识别不能被 agent 撤换，只能上报为待复核；
  - 改正字段只在来源记录的值与当前值一致时成立；
  - 改正人工值、ComicInfo 导入的值、锁定字段，都被拒绝；
  - 改正可以撤销；
  - 人撤换识别时，旧条目记为排除候选。
- **上报**：
  - 识别类上报使系列进入待人工；
  - 非识别类上报不改变识别状态，可以关闭；
  - 只读凭据可以上报，但不能领取或写入；
  - 普通用户的凭据只能读和上报。
- **工具面**：
  - 下线的工具不出现在清单里，调用时被统一拒绝；
  - 每个结果都有文本副本；
  - `missing_fields` 在任一字段缺失时命中；
  - 能力映射与清单过滤一致；
  - 初始化结果带有主循环说明；
  - 已有的额度记录数据保留。
- **人的界面**：
  - 待人工页的挑候选、否决、判查无此作、设已审定和重搜都能完成；
  - 详情页撤换识别会记下排除候选；
  - 手动搜索弹窗挑中即记为人工确认；
  - 识别状态筛选可用。

### 参考性真机验收（不作硬性门禁）

在 4 个系列的测试资料库上，用本机 qwen3.8-flash-next q2 加 pi，15 分钟内让全部系列进入已识别、查无此作或待人工之一，全程不调用 bash 或 curl，也不读仓库文件。结果记在本 effort 的验收材料里，作为工具契约对弱模型是否自解释的参考。

## Out of Scope

- 抽检视图。
- 服务端对确定性命中的自动认定，例如 ComicInfo 带来源 ID 时直接认定。等证据包积累出命中分布数据后再评估。
- 已识别系列中可变字段（连载状态、卷数）的定期刷新。
- 把来源原名或别名做成可搜索的字段。识别结论里会保存它们，但本轮不新增系列字段。
- 目录分组修复、重复系列合并、全局标签改名或合并。本轮只提供只读原语和上报。
- 常驻 agent，以及扫描后把系列推给 agent。
- MCP 内部模型辅助。
- 新启用来源时重新处理已识别的系列。本轮只重开查无此作的系列。

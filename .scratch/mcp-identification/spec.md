# MCP 系列识别与批量整理

Status: ready-for-agent

## Problem Statement

藏书共 62,960 个系列、682,641 本书、约 2,361 万页、9.6TB；每周新增几十本书，多数是已有系列追加新书。旧的整理方式是按目录名在 Bangumi 搜索、取第一条结果生成提案，再逐条人工审核。首轮扫描后的审核还剩 700 多条积压；批量刮削会把已经人工处理过的系列重新走一遍，所以后续新增的系列都没有再刮削，真正缺元数据的系列远多于积压的提案。

首版 MCP（effort `mcp-library`）本意是让 agent 分担这件事。实际试用：本机运行的 qwen3.8-flash-next q2 量化模型，经 ThinkRail 接入 pi，在 4 个系列的测试资料库上跑了近两个小时，没有成功写入任何一条元数据。会话里能逐条对上的原因：

- 客户端读不到 `structuredContent`，agent 改用 bash 和 curl 直接调 HTTP（结果的文本副本已在 `bb47092b` 恢复）。
- `missing_fields` 要求所列字段全部缺失才命中，「找缺元数据的系列」得到空集，agent 由此认定没有要处理的系列。
- 读工具描述理解不了身份/版本确认的含义，agent 转去仓库里读规格。
- 不存在的对象也返回统一拒绝，agent 误以为是权限问题。
- 26 个工具及其长描述占满上下文，多次压缩后计划丢失。
- 工具没有说明有权限即可直接写入，agent 停下来准备请示人。
- 搜索词要 agent 自己拼。

结构性的根因有三条：
- 一个系列要经过约八次细粒度调用，组装提案和写入请求的工作全落在 agent 身上；
- 没有任何持久记录说明「这个系列已经处理过、结论是什么」，上报过或查无此作的系列每一轮都会被重新捞出；
- 首次扫描把标题设为目录名并锁定，「锁定不动、非空不改」的补充规则因此永远补不上标题。

## Solution

把**系列识别**（某系列与某来源条目是同一部作品、同一版本的结论）做成按「系列 × 来源」持久保存的结论，并由它推导**识别状态**。

服务端负责三件事：
- 预先为「未处理」的系列多来源搜索，持久保存**证据包**；
- agent 确认识别后，按确定性策略执行元数据补充；
- 从历史提案推导存量系列的初始状态。

agent 只做身份裁决：成批领取证据包，对每个系列判定「识别为某候选」「查无此作」或**上报**；在受限边界内保留纠正能力。人只处理上报与待复核的系列，并可把系列设为**已审定**，让识别流程不再碰它。

MCP 工具面收缩为一个四工具主循环加若干原语，契约按「最弱的本地模型也能走完主循环」来约束。决策理由见 ADR 0017（draft）。

## User Stories

1. 作为资料库所有者，我希望 agent 只把拿不准的系列交给我，以便六万个系列的整理不再需要我逐条审核。
2. 作为资料库所有者，我希望每个系列的识别结论被持久记住，以便已处理的系列不会在下一轮被重新处理。
3. 作为资料库所有者，我希望新出现的系列自然处于未处理状态，以便增量整理不需要记住上次处理到哪里。
4. 作为资料库所有者，我希望已识别系列追加新书时不被重新识别，以便连载追加不制造重复工作。
5. 作为资料库所有者，我希望新书的本地线索与识别结论矛盾时，系列被标为待复核，以便错误识别能被发现。
6. 作为 agent 操作者，我希望一次领取一批系列及其证据包、一次提交整批裁决，以便每个系列不再需要八次调用。
7. 作为 agent 操作者，我希望证据包由服务端预先搜索并保存，以便领取时不用等待，证据也不会在处理途中过期。
8. 作为 agent 操作者，我希望搜索词由服务端根据目录名和 ComicInfo 生成，以便不必自己拼搜索词。
9. 作为 agent 操作者，我希望每个候选附带可核对的比对信号，以便弱模型也能判断，而不必解读来源可信度。
10. 作为 agent 操作者，我希望多个会话并行领取时不会拿到同一批系列，以便可以同时开多个 agent。
11. 作为 agent 操作者，我希望领取后中断的系列在租约到期后自动退回，以便崩溃的会话不会永久占住系列。
12. 作为 agent 操作者，我希望对难判的系列用自定义搜索词重搜，以便目录名噪声严重时也能找到条目。
13. 作为 agent 操作者，我希望按需查看本地封面、指定页缩略图和候选封面，以便有视觉能力的模型能区分相似候选。
14. 作为资料库所有者，我希望查无此作的结论记录搜过哪些来源，以便新启用来源时只对新来源重试。
15. 作为资料库所有者，我希望识别确认后服务端自动补充元数据，以便 agent 不必逐字段组装写入请求。
16. 作为资料库所有者，我希望文本字段按可配置的来源优先级取值，以便多来源识别时结果可预期。
17. 作为资料库所有者，我希望综合评分对所有已识别来源等权计算，并在新来源识别到达时重算由公式得出的评分。
18. 作为资料库所有者，我希望来源标签经投票阈值、黑名单和数量上限过滤后才追加，以便噪声标签不进入藏书。
19. 作为资料库所有者，我希望扫描生成的目录名标题在识别后被来源标题替换，人改过的标题不被替换。
20. 作为资料库所有者，我希望 agent 能撤换自己做出的错误识别，并撤回该识别带来、之后未被改动的字段。
21. 作为资料库所有者，我希望 agent 能改正来自来源且之后未被人改过的字段，并留下原因和可撤销的收据。
22. 作为资料库所有者，我希望人工编辑过的值、锁定字段、人工封面和人确认的识别永远不被 agent 改动，agent 只能把系列标为待复核。
23. 作为资料库所有者，我希望我否决过的条目不再被识别为该系列，以便同样的错误不会重复出现。
24. 作为资料库所有者，我希望历史上已应用的提案被视为人工确认的识别，以便过去的裁决不被重做。
25. 作为资料库所有者，我希望积压的待审提案在系列被识别后以「被识别取代」结案，并能与驳回区分。
26. 作为资料库所有者，我希望把系列设为已审定、随时可撤回，以便识别流程不再领取或补充它。
27. 作为资料库所有者，我希望在一个页面处理所有识别类上报和待复核系列：挑候选、判查无此作、自定义重搜或设为已审定。
28. 作为资料库所有者，我希望目录分组、重复和标签类上报以备注形式出现在同一页面，并且不阻塞识别。
29. 作为资料库所有者，我希望在系列详情页看到各来源的识别结论、确认者和确认时间，并能撤换识别。
30. 作为资料库所有者，我希望按识别状态筛选资料库。
31. 作为资料库所有者，我希望单系列手动搜索时挑中的条目直接记为人工确认的识别。
32. 作为资料库所有者，我希望批量刮削入口改为启动证据包预取，以便不再批量产生首条结果提案。
33. 作为资料库所有者，我希望只读 agent 能巡检重复、目录分组和标签问题并上报，但不能改动任何内容。
34. 作为 agent 操作者，我希望能在系列上添加作品群关系，并且可以撤销。
35. 作为 agent 操作者，我希望工具描述简短、带示例，拒绝时提示下一步，以便弱模型不读仓库也能走完主循环。
36. 作为 agent 操作者，我希望每个工具结果都有可读的文本副本，以便只读取文本内容的客户端也能工作。
37. 作为 agent 操作者，我希望 `missing_fields` 在任一所列字段缺失时即命中。
38. 作为资料库所有者，我希望 MCP 不再暴露内部模型额度工具，以便工具面只保留 agent 真正需要的能力。

## Implementation Decisions

### 识别结论与识别状态

- 识别结论按「系列 × 来源」保存，内容包括来源条目、确认者类别（人或 agent，含凭据归属）、确认时间、一句可核查的理由，以及来源条目的原名与别名。一个系列可以同时识别到多个来源。
- 识别状态由结论推导，不单独编辑：未处理、已识别、待人工、待复核、查无此作、已审定。查无此作要记录判定时搜过的来源；之后新启用的来源只让该系列对这个新来源重新变为可处理。
- **排除候选**随系列保存，只由人的否决产生，比如人撤换识别、驳回提案、在待人工页否决。证据包和提交裁决都排除这些条目。
- **已审定**由人设置、可以撤回。设置后 agent 不会领取该系列，识别流程也不为它补充元数据。
- 不设常驻 agent，也不在扫描后把系列推给 agent。agent 按识别状态拉取，增量不需要水位。
- 系列加入新书不影响已有识别。新书的本地线索与识别结论矛盾时（例如 ComicInfo 系列名指向另一部作品），系列转为待复核；原识别带来的字段保持不变。
- 持久化只规定逻辑需求：识别结论、排除候选、上报及其处理结果、已审定、证据包与抓取时间、领取租约。表名和存储布局在实施时决定。

### 存量初始状态

上线时一次性从历史推导，可以重复执行而不改变结果：
- 已应用的提案 → 对应来源的人工确认识别，条目取自提案的来源 ID。
- 被驳回的提案 → 对应条目记为排除候选，系列保持未处理。
- 待审提案 → 系列保持未处理；该系列识别完成后，这些提案以「被识别取代」结案。这是区别于驳回的终态，遵守 ADR 0011 的事务内终态守卫。
- 其余系列一律未处理。识别后的补充只填空值、不覆盖人改过的值，所以人工整理过的系列被重新处理也不会损失内容；不想让流程触碰的系列由人设为已审定。

### 证据包与预取

- **预取**是后台运行：
  - 存量回填由人手动启动，可以暂停、续跑；
  - 扫描结束后串联一次低优先级预取，只处理新出现的未处理系列；
  - 领取时证据包抓取时间超过 30 天，就在后台刷新。

  各来源限速由服务端统一控制。参与搜索的来源沿用现有多来源搜索的范围：已配置的目录型来源，不包括 LLM。
- **搜索词**由服务端确定性生成多个变体：清洗目录名中的卷号、汉化组、方括号标签等噪声，再加上 ComicInfo 的系列名和作者。人或 agent 可以对单个系列用自定义词重搜。
- **证据包**只含文本：
  - 本地线索：目录名、书数、前几本书的文件名、ComicInfo 的系列名、作者和年份；
  - 每个来源最多 3 条候选：标题、原名、作者、年份、卷数、简介摘要；
  - 每条候选附**比对信号**，例如标题规范化后一致、作者与 ComicInfo 一致、来源卷数和本地书数。比对信号是可核对的事实，不是匹配概率，与 metadata 规格中「来源 confidence 不是身份概率」一致。

  排除候选不进证据包。每批最多 20 个系列，整体响应保持在约 30 KB 量级。
- 证据包还没就绪的系列不会被发放。领取时如果没有可发放的系列，响应要说明预取排队情况。

### 识别后的元数据补充

识别确认（无论由 agent 还是人）后，服务端在同一项系列操作里补充元数据，复用现有补充收据与撤销机制：
- 文本字段（标题、简介、出版社、状态）按来源优先级取第一个有值的，默认顺序是 Bangumi > AniList > MangaDex > MyAnimeList > Comic Vine，可在配置里调整。Bangumi 标题取中文名，没有中文名时取原名。
- 综合评分仍只在缺失时生成，对所有已识别来源的有效评分换算成十分制后等权平均，保留原始分数、尺度和公式。新来源识别到达时，如果当前评分仍来自公式而且没被人改过，就重新计算。
- 标签和来源链接取所有已识别来源的并集，只追加。标签依次过三道：来源投票数阈值、可配置的黑名单（媒介、地区、年份、个人状态等）、每个系列的追加上限。Bangumi 标签需要保留投票数，目前取回时投票数被丢弃了。
- 作者以优先级最高的来源为准，其它来源只补充缺失的角色。
- **标题占位例外**：扫描生成的标题等于目录名并且被锁定。当前标题仍与系列目录名完全一致时，视为占位值，识别后可以替换为来源标题，替换后保留锁，以免重扫时被覆盖。标题与目录名不同即视为人改过，受保护。
- 封面不随识别自动替换。封面改善作为 agent 可选原语，沿用现有「只改未锁定的归档自动封面，人工封面受保护」规则。

### 纠正边界

agent 能做的：
- **撤换识别**：只限 agent 确认的识别。服务端撤回旧识别带来、之后未被改动的字段（沿用现有撤销的期望值校验），再按新识别补充。
- **改正字段**：只限当前值有来源记录、并且来源记录里的值与当前值一致的字段。人工编辑不写来源记录，ComicInfo 导入的值也没有来源记录，这两类都视为受保护。每次改正都要写原因、留收据、可以撤销。
- 作者校正与封面改善保留为独立原语，规则沿用现有系列内校正和封面保护。

agent 不能做的：
- 改动人工编辑过的值、锁定字段（标题占位例外由服务端执行，不对 agent 开放）、人工封面，以及人确认的识别。对人确认的识别，agent 只能上报待复核。

人在网页上撤换识别时，旧条目记为排除候选。

### agent 工具面

**主循环**（四个工具）：
1. **领取一批**：可按资料库过滤，每批最多 20 个。返回证据包和租约；租约到期后，未提交的系列退回未处理。
2. **提交裁决**：每个系列一条，取值为「识别为某来源的某候选」（可同时识别多个来源）、「查无此作」或「上报」（带分类），附一句理由。结果逐系列返回，不保证整批原子。同一请求键重放时返回原结果。
3. **重搜单个系列**：自定义搜索词，结果并入该系列的证据包。
4. **查看进度**：各识别状态下的系列数和预取情况。

**原语**（不在主循环里）：
- 撤换识别、改正字段、作者校正、封面改善；
- 取识别图片：本地封面、指定 1–3 页缩略图，以及证据包候选的封面。候选封面由服务端只从已知来源域名拉取、缩成小图，沿用现有图片体积预算；
- 作品群关系写入（系列内、可撤销）；
- 撤销与收据查询（沿用现有工具）；
- 扩展只读：按名称和身份跨资料库查重、目录与书名证据、标签统计；
- 上报（带分类）。

**上报分类**：
- 识别类：多候选难分、版本不确定、来源无结果但疑似存在。这类上报使系列进入待人工。
- 非识别类：疑似目录分组错误、疑似重复、标签问题。这类只挂备注，不改变识别状态。

**下线**：
- 来源搜索、读取搜索、提出匹配、读取匹配提案、读取补充状态、逐系列补充与批量补充，即现有 `library_search_sources`、`library_get_source_search`、`library_propose_match`、`library_get_match_proposal`、`library_get_enrichment_state`、`library_enrich_metadata`、`library_enrich_metadata_batch`；其中的作者校正与封面能力迁移到上面的原语。
- `library_assess_match`、`library_get_model_operation` 与 `internal_llm` 能力。已有的额度记录保留，只读不删。只有一位所有者使用，不设过渡期。

**能力映射**（不新增能力）：
- 领取、提交、重搜、撤换、改正、作者校正、封面、作品群关系写入、撤销：归 `metadata_write`。
- 进度查询、取识别图片、扩展只读、上报：归 `read`。普通用户的凭据仍然只有 `read` 生效，这样的凭据只能巡检和上报。
- `cleanup` 与运行类工具不变。

**契约整改**：
- 每个结果都带 JSON 文本副本，并加回归测试守住。
- 初始化时的 `instructions` 写明主循环配方：领取 → 提交 → 难判上报，有权限即可直接写入，无需请示人。
- 每个工具描述控制在约 400 字符以内并附一个调用示例。
- 拒绝时附下一步提示，但不泄露对象是否存在，例如提示「ID 应取自本次领取结果」。
- `find_series` 的 `missing_fields` 改为任一字段缺失即命中。
- 工具清单继续按当前能力过滤。

### 人的界面

- **待人工页**：列出识别类上报和待复核的系列，显示证据包和 agent 的理由，可按分类筛选。可做的操作：挑候选（记为人工确认，随即补充）、判查无此作、自定义重搜、设为已审定、否决候选（记为排除候选）。非识别类上报也在这一页，处理完可以关闭。
- **系列详情页**：显示各来源的识别结论、确认者和时间，提供撤换识别、设为已审定或撤回已审定的操作。
- **资料库筛选**：增加识别状态条件。
- **单系列手动搜索弹窗**：挑中条目即记为人工确认的识别，并按上面的策略补充。
- **批量刮削入口**（全库、资料库两个）改为启动证据包预取，不再批量生成首条结果提案。
- 不做抽检视图。

### 与既有决定的关系

- ADR 0017（draft）记录本次取舍，推翻 `mcp-library` 规划中「不建立待办、增量水位或维护状态机」的排除项。常驻 agent 和扫描后推给 agent 仍然排除。
- ADR 0016 中内部模型额度委托的部分随 `internal_llm` 下线而失效。实施交付时将该部分标为 deprecated 并链接 ADR 0017；清理自主权部分继续有效。在功能实际下线前不改它的状态，以免规格先于代码失真。
- ADR 0011 继续约束「被识别取代」结案以及所有由识别触发的写入。
- 长期契约在实施时归还所属规格：领域词汇已写入 `GLOSSARY.md`；跨模块边界写入 `architecture.md` 的 MCP 节；用例契约写入 `internal/application/SPEC.md`；协议契约写入 api 规格。

## Testing Decisions

优先在最高公开边界验证可观察行为。主要接缝沿用 `mcp-library` 已经建立的做法：用 `bootstrap.Open` 组装真实服务，经通用 MCP 客户端（官方 Go SDK）和管理员网页 HTTP 操作；使用真实的临时 SQLite、资料库和归档；外部来源经 `bootstrap.Options.Sources` 注入替身。现有的 `mcp_*_test.go` 集成测试是先例。

**核心场景**
- **识别状态**：
  - 从未处理到已识别、查无此作、待人工的推导；
  - 已审定的系列不被领取也不被补充，撤回后恢复；
  - 新书线索矛盾时转为待复核，原字段不变；
  - 新书线索不矛盾时状态不变；
  - 新启用来源后，查无此作的系列只对该来源重新可处理。
- **存量推导**：
  - 已应用提案 → 人工确认的识别；
  - 驳回提案 → 排除候选，并且不出现在证据包里；
  - 待审提案在识别后以被识别取代结案，可与驳回区分；
  - 推导可以重复执行。
- **领取与租约**：
  - 两个会话并行领取不重叠；
  - 租约到期后系列退回；
  - 证据包未就绪的系列不发放；
  - 整批提交时部分成功如实报告；
  - 请求键重放返回原结果。
- **预取**：
  - 手动回填可以暂停和续跑；
  - 扫描串联的预取只处理新的未处理系列；
  - 过期的证据包在领取时刷新；
  - 搜索词变体由目录名和 ComicInfo 生成；
  - 单个来源失败不拖垮整个证据包。
- **补充策略**：
  - 来源优先级取值；
  - 多来源等权评分，以及新来源到达时只重算公式评分；
  - 标签的投票阈值、黑名单和上限；
  - 链接取并集；
  - 标题占位替换，以及人改过的标题受保护；
  - 锁定字段和非空人工值不变。
- **纠正边界**：
  - 撤换 agent 识别时，撤回未改动的字段并按新识别补充；
  - 人确认的识别不能被 agent 撤换，只能上报待复核；
  - 改正字段只限来源记录值与当前值一致的情况；
  - 人工值、ComicInfo 导入的值和锁定字段都被拒绝；
  - 改正可以撤销。
- **上报**：
  - 识别类上报进入待人工；
  - 非识别类上报不改变识别状态；
  - 只读凭据可以上报，但不能领取或写入。
- **工具面**：
  - 下线的工具不出现在清单里，调用时被统一拒绝；
  - 每个结果都有文本副本；
  - `missing_fields` 按任一字段缺失命中；
  - 能力映射与清单过滤一致。
- **人的界面**：
  - 待人工页的挑候选、否决、查无此作、已审定、重搜；
  - 详情页撤换识别会记下排除候选；
  - 手动搜索弹窗挑中即记为人工确认。

  组件测试参考现有元数据审核和账户管理测试，但它们不能替代真实服务的授权验收。

**参考性真机验收（不作硬性门禁）**：在 4 个系列的测试资料库上，用本机 qwen3.8-flash-next q2 加 pi，15 分钟内让全部系列进入已识别、查无此作或待人工之一，全程不调用 bash 或 curl，也不读仓库文件。结果记录在本 effort 的验收材料里，作为工具契约是否对弱模型自解释的参考。

**保留既有守卫**：提案事务竞争、字段锁、人工封面保护、撤销冲突、清理边界、凭据撤销与检查点取消、stdio 代理测试都继续保留。新路径要补自己的回归，不把旧测试通过当作新功能已经具备。

## Out of Scope

- 抽检视图。
- 服务端对确定性命中的自动认定（例如 ComicInfo 带来源 ID）：等证据包积累出命中分布数据后再评估。
- 已识别系列中可变字段（连载状态、卷数）的定期刷新。
- 把来源原名或别名做成可搜索字段：识别结论里会保存它们，但本轮不新增系列字段。
- 目录分组修复、重复系列合并、全局标签改名或合并：本轮只提供只读原语和上报。
- 常驻 agent，以及扫描后把系列推给 agent。
- MCP 内部模型辅助。

## Further Notes

- **已核对的现状事实**（实施前请重新确认）：
  - `seriesmeta.PrepareScanInitial` 把标题设为目录名并锁定 `title`；
  - 字段来源记录只在应用提案和补充元数据时写入，人工编辑不写，但记录里存有当时写入的值；

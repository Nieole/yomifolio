# 系列识别是持久结论，agent 只裁决身份

藏书有六万余个系列。按系列与来源持久保存**系列识别**结论，并由它推导**识别状态**；agent 从服务端预先生成的**证据包**里成批领取系列，只裁决「是哪一部」或**上报**，识别确认后的元数据补充由服务端按确定性策略执行。之所以这样选，是因为不保存处理结论会让已上报、查无此作的系列在每一轮都被重新处理，增量也无从谈起；而让 agent 逐系列搜索、组装提案和写入请求，每个系列要七八次工具调用，弱模型在这些契约面前会迷路，强模型也要付出与藏书规模成正比的推理成本。

代价是引入了一份持久的处理结论，以及与之相伴的领取租约和预取运行，推翻了 MCP 资料库自动化规划中「不建立待办、增量水位或维护状态机」的排除项；补充策略（字段来源优先级、标签过滤、评分公式）从 agent 的判断变成服务端的配置，agent 只能在受限边界内纠正。仍然不设常驻 agent，扫描后也不把系列推给 agent：扫描最多串联服务端的候选预取，由 agent 按识别状态自行拉取。

## Considered Options

- **agent 逐系列使用细粒度工具（原设计）**：灵活，但调用次数与上下文开销随系列数线性增长，弱模型无法完成。
- **服务端遇到确定性命中直接认定**（如 ComicInfo 带来源 ID、标题作者卷数全部一致）：能进一步省掉 agent，但需要先有证据包的命中分布数据才能定阈值，暂不采用。

## Consequences

- 细粒度识别链（来源搜索、读取搜索、提出匹配、读取匹配提案、读取补充状态、逐系列及批量补充）与内部模型额度工具从 MCP 下线；作者校正与封面改善改为独立原语。ADR 0016 中关于内部模型额度委托的部分随实施失效，清理自主权部分不变。
- 扫描时以目录名生成并锁定的标题被视为占位值：当前标题仍等于目录名时，识别后可替换为来源标题，否则受保护。没有这条例外，锁定字段不动的规则会让识别永远补不上标题。
- 人否决过的来源条目作为**排除候选**随系列保留，不再进入证据包；历史上已应用的提案视为人工确认的识别。
- 识别带来的写入仍遵守 ADR 0011：提案终态与当前值、锁在写入事务内重读。

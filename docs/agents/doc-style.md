# 文档与注释

`AGENTS.md` 的 Documentation & Comments 一节是常驻判据，本文是那一节答不下的部分。动手前读与你要改的那部分相关的小节。

## 分层

每层只答一个问题。答不下的往下一层沉。

**Go**

| 层 | 位置 | 回答 | 预算 |
| --- | --- | --- | --- |
| 包 | `// Package xxx …`，由 `ST1000` 强制 | 这个包是什么、边界在哪 | 3–8 行 |
| 文件 | 文件顶部，与 `package` 之间空一行 | 本文件在包里占哪一块 | ≤5 行 |
| 符号 | 紧贴导出声明 | 契约：前置条件、并发要求、错误语义 | 一事一议 |
| 行内 | `//` | 为什么这么写 | 一两行 |

**文件头是可选的，且没有「改写」这一档。** 只有能说出一句从文件名与 package doc 推不出来的话时才写；
说不出就整块删掉。一句放到任何文件上都成立的话（「本文件是业务实现，属于 X 链路，负责 Y」），
相对于没有文件头是零差别，写它只是在收租。

**前端**：代码注释同上，去掉包这一层。TS 目录不是语言级的包，不用目录 README 模拟 package doc；跨文件的长期功能边界由 ThinkRail 规格承载，见下节。文件头写在所有 `import` 之前，符号 doc 紧贴声明；位置就是分层。

**测试文件**：文件头只答**这些测试在守哪条不变量、破了会怎样**。测试名已经答了测什么，断言已经答了怎么判。

## 归属

### 内容归哪个文件

按**读者**分；重叠时看谁会来读。

| 文件 | 读者 | 独占 |
| --- | --- | --- |
| `README.md` | 用户、部署者 | 是什么、能干什么、怎么装、怎么配 |
| `AGENTS.md` | 在仓库里干活的人和 agent | 结构、命令、风格、约定 |
| `GLOSSARY.md` | 两者 | 只有词汇，没有实现 |
| 根目标、架构与模块规格 | 维护者与 agent | 当前目标、责任、边界与公开契约 |
| `docs/adr/` | 要改架构的人 | 拦阻性决策及其历史理由 |
| `docs/agents/` | agent | 技能协作细节 |
| `CHANGELOG.md` | 用户 | 版本史 |
| `.scratch/` | 干活的人 | effort 规划、工单、验收与延期记录 |

环境本身也是一处归属。写进文档的应当是环境里查不到的东西：不成文的约定、某个选择背后的理由、配置文件不会承认的坑。`package.json` 的脚本名、`config.example.yaml` 的字段、`--help` 的输出一次查询就能拿到，留在环境里，那里不会过期。

### ThinkRail 规格

根 `goal-and-requirements.md` 回答产品目标与范围，`architecture.md` 回答跨模块边界和实际依赖；模块旁的 `SPEC.md` 回答自身责任、公开契约、禁止越界及重要限制。独立子能力可在实现旁单列具名规格（如 `SEARCH-SPEC.md`），父规格留入口，不复制细节。是否拆分取决于独立契约和读者，不按每个目录机械建文件。

`GLOSSARY.md` 定义领域语言；ADR 保存跨切面决定及理由。二者通过 `id`、`type` 元数据进入同一规格图，ADR 的历史论据不按现状重写。已被取代的决定标 `deprecated` 并链接后继；当前模块不能继续把它当有效约束。

事实只归一处，其他规格按稳定 ID 引用；跨兄弟模块的实际依赖集中在架构节点。核对入口可列符号与测试，但不把代码清单、易变常量或当次验收结果写成永久契约。已有测试只说明有守卫，静态核对不等于测试通过。发现实现与有效契约冲突时单列疑点，不用改文档把缺陷合理化。

图元数据及结构使用 `spec_create`、`spec_update`、`spec_delete` 维护，正文使用普通编辑工具；改结构后运行 `spec_validate`。首次纳入只有正文或缺少 ID 的现有文件时，先补齐可索引元数据，保留原正文及稳定编号，再使用图工具维护。

ThinkRail 的临时工作设计放在 `.thinkrail/context/TASK-<slug>.md`，完成后将长期内容归还所属规格并移除该临时节点；不把其他工作的任务文档或 `.scratch/` 验收材料批量提升为长期节点。新增及推导出的规格先用 draft，待用户审阅后再转 active；不因代码或测试文件存在就自动转 active。正式交付的当前行为另按代码与有效决策核实。

### 历史归哪里

对用户的版本史归 `CHANGELOG.md`，决策史归 `docs/adr/`，工作过程与当次验收证据归 `.scratch/`。碰到带历史的注释，按顺序判：

1. 剥掉历史后剩下的能写成一条**约束**（必须 / 不得 / 否则会…）→ 就地改写成约束，历史丢弃。
2. 写不成约束，但这段历史**拦得住一个看起来明显正确的改动** → 升 ADR，注释里留结论加引用。
3. 都不是 → 删。

## 不会腐坏的引用

引用代码写**符号名**，跨包写 `包名.符号名`：重命名时它跟着改，grep 找得到，IDE 跳得过去。文档里写路径。

随代码漂移的现状数字与位置会腐坏，而且腐坏时没有任何机制会报警：行号、出现次数、包或文件的行数、「上面那个函数」「见下方」。

一次测量得到的结论不是现状快照——「实测 UNION 形态比 instr 全表扫快一倍」带时间戳语义，别人改代码改不坏它。这类结论写进 ADR。

## 一个完整的例子

下面这 13 行文件头把三种内容混在了一起（取自 `internal/api/task_engine.go` 改写前）：

```go
// 本文件是后台任务引擎，持有任务子域的**全部可变状态**并独占其锁。
//
// 此前这些状态挂在 taskEngine 上、方法却挂在 Controller 上（`c.taskEngine.xxx` 出现 130+ 次），
// 于是「谁能改任务表」这条边界在 17.9k 行的 api 包里没有任何结构约束……
//
// 并发约定：
//   - 除 relaunchers 外，全部字段由 mutex 保护。
//   - 名字带 Locked 后缀的方法要求调用方已持锁。
//   - 任何要把 TaskStatus 带出临界区的路径必须先 cloneTaskStatus，否则……
```

三段各有去处：

- 第一段答的是「本文件占哪一块」，**留在文件头**。
- 并发约定是类型契约，**沉到 `taskEngine` 的符号 doc**。
- 中间那段剥掉历史后，残值是一条约束——「Controller 不得直接触碰任务表」。写成约束之后历史丢弃，`130+ 次` 与 `17.9k 行` 随之消失。

文件头剩两行：

```go
// 后台任务引擎。任务子域的全部可变状态归它所有，只依赖三样外部能力：落盘的 store、
// 投递 SSE 的 publish、感知停机的 done。Controller 不得直接触碰任务表。
```

## 检查器

`scripts/check-doc-style.sh` 全量扫描，本地跑：

- **拦截**：文件头超预算；行号与现状统计数字。
- **提示**：疑似历史叙述的词（原来 / 之前 / 不再 / 旧的）。这一项误报多——「距 t 若干天之前」是业务语义不是历史——所以只打印不拦截，由你按上面的三段判定逐条处置。

包注释的存在性由 `.golangci.yml` 的 `ST1000` 强制，不在脚本里重复检查。
